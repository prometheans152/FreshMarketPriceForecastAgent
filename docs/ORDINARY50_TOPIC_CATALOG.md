## U01｜記錄吃過的食物時，分清生熟與去皮

- **公開訓練起點／本人輸入：** TFDA食品營養；食材名稱、生熟狀態；克重自行量。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_HOME_MONEY，HM01](research/ORDINARY50_HOME_MONEY.md)。

- **狀態／用途與最低成果：** 候選。給一般做飯／記飲食的人：輸入「熟白芝麻 15g」「馬鈴薯去皮後 121g」，找出對應食品身份及營養資料，缺少生熟資訊就保留候選並追問。最低成果是正確食物記錄及依已確認克重計算；不推估治療、疾病或該吃多少。
- **學習目標與真值：** 名稱＋處理狀態 → `整合編號` 的配對排序模型。`樣品名稱`、`俗名`、`內容物描述` 是公開輸入與真身份；把俗名或刪去狀態形成訓練查詢是**明示派生**。每 100 克含量是真分析欄位，營養加總用算式，不把算式冒充模型。自己的熟重／可食重沒有公開真值，不從生食資料憑空換算。
- **公開資料：** [TFDA 食品營養成分資料集](https://data.gov.tw/dataset/8543)，頁面更新 2026-08-27，每 3 月更新，[政府資料開放授權條款第 1 版](https://data.gov.tw/license)。[CSV 下載](https://data.fda.gov.tw/data/opendata/export/20/csv) 本輪 HTTP 200，實際為 3,050,521 bytes ZIP，內 `20_2.csv` UTF-8，226,720 分析列、2,180 個 `整合編號`。不是 226,720 種獨立食物。
- **樣本／適配：** 已實讀 B0700201 馬鈴薯，俗名含洋芋／洋薯；描述為生、去皮；廢棄率 9.8。C1610101 白芝麻(熟) 的描述為熟(烤)，C1710101 是紅土帶殼花生(熟)。欄位含分析項、含量單位、每100克含量、樣本數。部分列含量空白、樣本數 0，不能當含量為 0；同食物多營養列須先依身份整併。臺灣食品與中文俗名原資料，無海外適配假設。
- **已有作品做什麼：** [營養成分小幫手](https://data.gov.tw/applications/135812) 已做食品營養查詢與攝取成分整理；再做一個食物→營養總量介面即淘汰。TFDA 官方查詢也已可依名稱找資料。
- **本題另測什麼／基準：** 測家庭俗稱加「去皮、生、熟、乾貨」後，會否仍錯套到另一種處理狀態。比較精確字串／編輯距離搜尋、只看名稱的排序模型、名稱＋狀態模型；測身份 Top-1、錯套生熟／可食部的比例，並在已確認身份的子集才算營養總量誤差。不是單純換門檻。
- **低成本私有資料／獨立測試：** 自家 20–30 種常用食材，各 2–3 種真實叫法及狀態；有秤才另做約 10 次處理前後重量。先由人對照官方身份。公共別名增強以食物身份／同食物生熟族分組；自家校正與測試按食材族及後續做飯日期分開，不能讓同一食材的別名跨兩邊。
- **限制／下一步：** 公開食品未必有自己做法或調味，缺身份就不能承諾營養準確。先列出 20 種目標食品是否真有對應狀態，沒有則縮範圍；不能將食品描述的「熟」當作所有家庭加熱方法相同。資料與訓練方案已查，模型、自家效果都未驗證。

## U02｜看懂零食成分：複方不被誤當單一添加物

- **公開訓練起點／本人輸入：** TFDA食品添加物；包裝成分文字或局部照片。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_HOME_MONEY，HM02](research/ORDINARY50_HOME_MONEY.md)。

- **狀態／用途與最低成果：** 候選。一般買零食的人貼成分文字或自己的包裝局部照片，得到「已對到哪個官方成分、屬於哪個括號複方、哪些仍未知」及原來源。最低成果是成分身份與嵌套結構對齊，不給安全性、合法性或過敏食用結論。
- **學習目標與真值：** 成分片段 → 官方中英同物質名稱；公開中英對是真配對，括號結構與複方拆解是用官方例子／自己的包裝人工標出的**代理／私有標籤**。訓練配對模型含「非同物質」近名負例；另學習分段關係，不能把複方商品名直接替換成某一純物質。官方用途類別是真欄位，不能由類別推出實際包裝添加量。
- **公開資料：** [TFDA 食品添加物使用範圍及限量暨規格標準](https://data.gov.tw/dataset/9640)，頁面更新 2025-11-25、不定期更新、政府資料開放授權第 1 版。[InfoId=61 JSON](https://data.fda.gov.tw/opendata/exportDataList.do?InfoId=61&logType=5&method=ExportData) 本輪 HTTP 200、976,647 bytes、804 列；歷史快照可用，不說 804 種為未來持續有效的法律名單。另讀官方 [添加物常用別名](https://www.fda.gov.tw/TC/siteContent.aspx?sid=10159) 與 [常用複方名稱](https://www.fda.gov.tw/TC/siteContent.aspx?sid=10160) 頁面；其網頁授權沒有另外推定成可再散布影像資料集。
- **樣本／適配：** 實讀欄位 `類別`、`中文品名`、`英文品名`、`使用食品範圍及限量`、`使用限制`、`規格`、`類別說明`；樣本己二烯酸／SorbicAcid、己二烯酸鉀／PotassiumSorbate。原欄位保留空格／拼法，正規化只作模型副本。這是臺灣官方名稱，不用海外配方表冒充臺灣包裝真標籤。
- **已有作品做什麼：** [食覺 FoodSense](https://www.foodsense.tw/) 已提供照片／條碼／手動輸入成分、添加物解讀及個人化飲食觀點；單純拍照解說添加物不保留。官方別名表也已能人工查詢。
- **本題另測什麼／基準：** 測「複方括號內有多項、鹽類名稱只差一字、OCR 丟括號」造成的錯併，而不是比較誰講的健康建議好。對照原名精確查表、逗號分割＋字典、平面語意匹配、保留括號關係的配對模型；主要指標為整個成分清單的身份及父子關係正確率、把複方錯當純物質率、未收錄物質錯配率。FoodSense 本輪只查功能宣告，未登入跑其模型，不能聲稱勝過產品。
- **低成本私有資料／獨立測試：** 自家 20–30 個用過的空包裝，保留成分局部照片及人核對文字，約 80–150 個已確認名稱片段；人工標括號歸屬。依完整產品／配方群分組；同一包裝的重拍、合成 OCR 字錯不能跨測試。先公共訓練，再比較未校正與只用訓練包裝校正。
- **限制／下一步：** 沒有完整公開臺灣包裝影像及複方真標籤，身份配對公共資料足夠起步，但複方效果必須靠小量真包裝獨立測；看不見的配方比例不補寫。選中後先核 20 個包裝是否有足夠括號／近名錯例，否則此差異不成立而撤下。

- **低成本私有資料／獨立測試：** 一副已有紙牌，做 15–25 次人工取走 0–3 張的盤點短片，記取走真值、重複展示和實體编號；另外至少一副不同字角牌測試。按整副牌、整段盤點流程分組，鄰近幀不跨組。比較同額自己標記前後的改善。
- **限制／下一步：** 普通單副52牌無需辨認同花同數字的副本身份；若簡單類集合已經夠用，應放棄更重追蹤模型，不能為課業強加複雜度。僅憑有限牌面可能分不清兩個實體；展示不完整時輸出「尚未看見」，不做物理缺失斷言。本題不沿用 W42 果袋同樹重複計數的物件任務。

## U08｜家庭棋局漏拍一步後，接回可確認的棋譜

- **公開訓練起點／本人輸入：** Chesscog棋盤/FEN；間歇棋盤照、已知起始棋局。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_HOME_MONEY，HM08](research/ORDINARY50_HOME_MONEY.md)。

- **狀態／用途與最低成果：** 候選，限國際西洋棋。家人從已知初始棋局開始，每隔一兩步拍盤面；偶尔漏拍時列出能符合兩端盤面的候選走法，唯一確定才接入棋譜，否則请人補该段。最低成果是棋譜續接，不輸出強行猜中的「完整真棋局」。
- **學習目標與真值：** 盤面照片 → FEN 棋子位置／`white_turn`，結合合法走法約束排序候選轉移。公開圖像真標籤含 FEN、棋子類別與框、四角。由既有合法走法產生跳過 1–2 步的序列是**派生標籤**；自己的實際 PGN 及拍攝步驟才是家庭真序列。單張棋子位置不能推知歷史王車易位權或吃過路兵，初始狀態必須提供。
- **公開資料：** [Chesscog 原作者](https://github.com/georg-wolflein/chesscog)，[OSF 資料 DOI](https://doi.org/10.17605/OSF.IO/XF3KA)，4,888 張 Blender 合成棋局圖，2021-04-25 建立、2023-02-21 節點更新；[OSF 授權 API](https://api.osf.io/v2/licenses/563c1cf88c5e4a3877f9e96a/) 實讀為 CC BY 4.0。靜態合成資料，無定期取樣。倉庫 commit `4e9c22d76c75615d4e9a4cd567679f4caa00dec7` 的 `data/fens.txt` 首段實讀；OSF `val.zip` 總 222,952,872 bytes，**僅以 HTTP 206 Range 取局部，不下載全集**。
- **樣本／臺灣對應：** ZIP 中 `val/0418.json` 536 compressed bytes 已完整解壓實讀：`fen=8/8/2Pk1p1p/p2B4/P4PP1/6K1/8/2b5`、`white_turn=false`，`camera.angle=45`，4 個 corners、11 個 piece/square/box。圖像 PNG 只取局部壓縮 bytes，未完成该 PNG 像素讀取。臺灣 [西洋棋推廣中心](https://www.chess.org.tw/) 有同一國際西洋棋游戲及 FIDE 脈絡；本題固定同一 8×8、六類棋子及 FEN／PGN 編碼，不是用中國象棋影像套海外標籤。
- **已有作品做什麼：** [Chesscog／原論文](https://doi.org/10.3390/jimaging7060094) 已做合成預訓練、盤面辨識及**只用兩張自家棋盤照片適配**；不能把兩張家庭校正當新的主要差異。[UCR 2024 畢業專題](https://escholarship.org/content/qt31d7k315/qt31d7k315_noSplash_25b4d0908ca6046aa33dda5f01db1f6e.pdf) 已做連續錄影、手部事件後辨識、前後占位差與合法單步檢驗，要求完整穩定視角；單純自動記棋譜已有人做。
- **本題另測什麼／基準：** 明示拿掉一次／兩次拍攝，測多步狀態差而非連續錄影完整單步。對照 Chesscog 每圖獨立辨識、前後差＋只容一合法步、容有限遺漏的候選轉移排序；各用同樣兩張家庭適配圖。測整段實際走法 exact match、錯誤接成唯一走法率、無法確認段數及人工補記次數，另列兩端盤面相同但走法多解的失敗例。不將合法性當真實歷史的充分條件。
- **低成本私有資料／獨立測試：** 家中一副棋，自己完成 10–15 個短局併保存真實走法與20–40照片；模擬漏拍時仍保留原真譜作評分。按整局／局面來源與棋具組分組，合法路徑的相鄰幀同組；至少留後續5局只測不改模型。
- **限制／下一步：** 這題識別模型已有強基準，收益來自漏拍恢復的明確使用條件。兩個盤面本來就可能有多個路徑，寧可列候選，不能捏造未觀察歷史。選中後補取一完整小 PNG／JSON 對及少量連續合法局面；本輪已經讀真標籤和授權，未證明相鄰原圖具有足夠連續性，不用它們偽造天然影片。

## U09｜十分鐘休息，挑自己做得完的西洋棋練習

- **公開訓練起點／本人輸入：** Lichess題目/解法；可用時間、自己解題計時。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_HOME_MONEY，HM09](research/ORDINARY50_HOME_MONEY.md)。

- **狀態／用途與最低成果：** 候選。普通愛好者輸入可用 5／10 分鐘和近期自己練習記錄，輸出一小組預計能在時限內嘗試完的題；最低成果對比按全球難度挑題是否更少超時。不宣稱短時段練習使棋力提高。

- **公開資料：** [Lichess 官方公開題庫](https://database.lichess.org/#puzzles) CC0、約每月發布；[官方 Hugging Face 快照](https://huggingface.co/datasets/Lichess/chess-puzzles) 2026-09 更新約 6,100,960 題。[first-rows 樣本](https://datasets-server.huggingface.co/first-rows?dataset=Lichess/chess-puzzles&config=default&split=train) HTTP 200，35,144 bytes，實讀首筆；完整約 304MB `.csv.zst` **沒有下載**。可從官方後續按小子集取得訓練，不能說這次已經讀數百万題。

- **已有作品做什麼：** [Lichess 主題訓練](https://lichess.org/training/themes) 已有主題與難度／個人題分；[EchoPuz 原作者方法](https://echopuz.com/how-it-works) 已從自己對局找關鍵局面、嵌入檢索近似題並自適應難度，不能再包裝成「個人化棋題推薦」。[Blunder Book](https://www.blunderbook.com/) 已做自己的失誤題及間隔重複。
- **本題另測什麼／基準：** 只驗證「實際時間時限」的個人完成預測，而非相似棋局或自己的弱點推薦。對照同主題固定全球 Rating、個人題分選題、固定解法長度、加自己歷史秒數的時間模型；以首次做新題的超時率、固定十分鐘完成且正確的題數、完成時間誤差為指標。題庫長短／全球難度只是代理先驗，若個人化時間並無收益就撤下。
- **低成本私有資料／獨立測試：** 30–60 次自己原本就會做的練習，記錄時間、結果、提示、暫停，不需要公開帳號或朋友資料。前20–30題校正，後續題時間切分；同 GameId、同局面近變形／曾經做過題保持同組。候選排序規則必須在測試前凍結；不把正好挑到做過的題算成功。
- **限制／下一步：** 這是少量私人時間真值不可省的題，公開資料本身不能訓出個人秒數。模型可利用公開真難度預訓練，但不能宣稱公開資料已包含所需最終標籤。不同休息中斷／疲勞讓小量計時有噪聲，先測一週記錄成本及基準即可，不需長期公司纪錄。

## U11｜家人說「那個杯子」，補問一項才拿對

- **公開訓練起點／本人輸入：** TaiwanVQA台灣圖；自家物品照片、家人稱呼。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_HOME_MONEY，HM11](research/ORDINARY50_HOME_MONEY.md)。

- **狀態／用途與最低成果：** 追加候選。家人看同一張桌面／櫃子照片說「拿黑杯子」「咖啡那個」，若有多件同類物品，提出能分開候選的一項問題，如「有吸管還是把手？」回答後圈出本人要的物品。最低成果限定一個家庭 15–25 件常用物品；不宣稱東西已移動後仍知道現址，也不控制機器拿取。

- **低成本私有資料／獨立測試：** 15–25 件杯／盒／小文具，一次人核實物 ID／框，2名家人各說1–2個自然叫法；15–20張包含2–5件物品照片及約40–60次回答。實物族／同件重拍分組，校正只用先前照片與明確叫法，後續新擺放和未在訓練出現的家人說法作測試。近義稱呼從同一人產生的擴充不能隨機跨測試。
- **限制／下一步／課程：** 私有實物身份標籤必要，公共 VQA 只支援語意／屬性預訓練；若家中每次只一個候選、或同款完全無可辨特徵，不需或無法澄清。不能從短暫照片推斷使用者內心意圖；先做一次真人可理解提問的小試，不把語句流暢當正確。模型＋候選提問代理人是可展示流程，尚未完成家庭驗證。

## U23｜開了降噪，聲音真的更好懂嗎

- **公開訓練起點／本人輸入：** 台灣TMHINT-QI評分；同段錄音的原音與降噪版。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_EVERYDAY_OFFICE，EO12](research/ORDINARY50_EVERYDAY_OFFICE.md)。

- **已有／另測：** [MOSA-Net+原研究](https://arxiv.org/abs/2309.12766)已提升品質／可懂度評分；[2026 MOS preference研究](https://aclanthology.org/2026.findings-acl.1638/)已研究語音兩兩偏好，不能把排序本身稱新；[Teams noise suppression](https://support.microsoft.com/en-au/teams/meetings/reduce-background-noise-in-microsoft-teams-meetings)已有降噪強度選項。本題另測**本人低音量／遠距離輸入和實際降噪工具，能否避免選到「安靜但吞字」的版本**，對照單段預測分數相減及總是開啟降噪。

- **限制／下一步：** 評分相近時不強行二選一；無足夠同句同噪條件配對則不能訓練這個目標。先點數配對及10組本地盲聽；若通用評分相減已完全解決，撤下。

**狀態：保留候選。** 普通人還沒選地點，先釐清此次是放鬆、吃美食、交通方便還是配合孩子；輸出三項有順序的取捨提示，讓使用者更快刪去不合的行程，不造出景點客觀品質排名。

- **輸入／輸出／真標籤**：輸入決策前的假日類型、計畫天數、出發縣市、同行家戶年齡人數、旅遊目的；輸出 `vq13_1..3` 有序理由。碼7紓解壓力／休閒／養生、5品嚐美食、8交通便利、11配合小孩喜好、12配合長輩喜好、9無障礙設施等。`vq13_1` 空白4,783，非空13,336；扣第一項65其他255，明列1–14理由13,081，後兩欄可缺答，不能補成排末。
- **資料及狀態**：A 的 113 國內個別旅次、OGDL-1、2024年度四季，字典與三個欄位實讀成功。例首筆理由7，與親子、老人等不同原碼保持不改名。公開的是事後回憶的選地考量，不是事前打分；不把已經到訪的目的地、實際住宿和實際支出加入輸入猜事前理由。
- **已有研究／產品／開源／校內作品**：[ICAPS 2016 個人與團體旅遊推薦](https://kwanhui.github.io/publications/2016-ICAPS-tourRecDC.pdf)以興趣及時間約束安排個人／團體景點；ATLAS 已有團體偏好共識。政大[國民旅遊卡行為與認知研究](https://thesis.lib.nccu.edu.tw/detail/4cec9ae140813ba5e3d06b0856b94029/?seq=8)公開摘要與目錄已有選地理由、旅遊行為交叉分析，目的為政策與經營參考。Booking.com 也已做目的地推薦。沒有將其當作未做過的「旅遊推薦」領域。
- **另外測什麼與基準**：本題不先推薦景點，而預測「這次該先比較什麼」。有序理由模型對照全體第一理由眾數、各欄獨立分類與直接沿用本人上次前三理由；用最多四趟本人排序回饋調整，測第一順位命中、前3順位 nDCG／序對反轉，以及本人明示第一需求（例如帶長輩交通便利）是否被排掉。再用相同三份候選行程供本人比較，記取捨是否縮短與拒絕原因，不稱原排序全球新方法。
- **自家成本與獨立分組**：6份已有行程每份補3項順序與完整日期／同行組合，約15–20分鐘；4調整、2整份留測。公開用同CASEID所有旅次一起切，訪問季時間與出發縣市留組；明示某理由根本不適用時各模型使用同樣遮罩。目的地未知的輸入場景與事後調查之間誤差另報。
- **限制／下一步**：前三理由存在沒有被問的第四以後因素；公開調查的排序不是本人快樂函數。若本人每次能用3次點選穩定說明需求，而模型不能減少重複輸入或排序錯誤，這題沒有繼續價值。先驗證需較少回饋時是否能可靠提取隨同行情境變化的次序。

## U33｜安排國旅行程，先保留自己比較喜歡的活動

- **公開訓練起點／本人輸入：** 台灣旅遊調查明確喜好；自己做過的活動與最喜歡項。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_COMMUTE，C05](research/ORDINARY50_COMMUTE.md)。

**狀態：保留候選。** 一般人的行程塞了健行、逛街、博物館與夜市但時間不夠時，先列出較值得本人保留的活動；最低成果是對用戶自己輸入的3–5項活動排順序，不自動宣稱每個景點都已驗證好玩。

- **公開真標籤與日常輸入**：`vq16_1..10` 是該趟**實際從事的活動集合**，`vq16a` 是其中「最喜歡」。模型輸入活動集合、出遊目的、天數與同行家戶年齡組，輸出集合內的最喜歡類別；自然海岸101、森林／步道102、美食501、購物603等保持原編碼。只訓練最喜歡項確實位於從事集合，剔除801無特殊偏好、998只記得一趟、999拒答、765其他。本次完整檢查得到 **17,730** 個滿足該條件的旅次。只有一個活動的樣本分開報告，不能拿必選唯一項刷高命中。
- **資料與適配**：A 的113年18,119國內旅次、OGDL-1、全年四季、CSV/字典實際已讀。最喜歡101有3,670、102有2,579、501有2,038、603有1,692等。公開從事集合受預算/機會限制，不等於任意活動都可選擇；私人行程也只能用同類活動映射，現存類別不對應的演出不能亂塞“藝文”當訓練真標籤。
- **已有人做什麼**：[POIBERT](https://arxiv.org/abs/2212.13900)已有依類別偏好、歷史軌跡與約束推薦POI；ICAPS 已做個人/團體興趣安排，ATLAS README 已有活動推薦與日程優化。官方調查也已統計最喜歡活動。政大上卡旅遊行為研究公開目錄有偏好活動統計。本題不聲稱活動推薦概念或個人適配首次出現。
- **另測的差異／對照**：區分「很多人做」與「參加後最喜歡」；比較活動發生頻率、人口最喜歡模型、本人前次最喜歡、少量情境反饋調正。同一個人獨旅偏好健行、親子偏好動物互動時，測錯誤延用上次偏好的比例，候選集內Top1/Top2命中與NDCG，以及“本人願意刪/最想留”誤推；要再問私人願意再做程度，不能只預測選中歷史類別就稱滿意提升。模型可採用集合條件分類，不讓`vq16a`進輸入。
- **採集與完整分組驗證**：6趟過往行程記錄活動集合、最喜歡、最不想再安排的活動與完整日期，約20分鐘；4用於調整，2完整行程留測。公開CASEID組+季度時間拆分，單項與多項候選分別報告，所有該趟的10項不可打散，陌生活動類別單獨標未知。第一版只能對自己的活動短名單排序，不建無真標籤的完整旅遊順序。
- **限制／下一步**：大類喜好不能推斷同類每個地點效果；旅客最喜歡是回憶、機會與疲累共同結果。少量家庭反饋不證明所有家庭都可用。先在多活動行程中檢查是否比“本人總選同類”基準更少把次要活動推上首位。

## U34｜找遺失物時，先補哪個線索能排除最多誤認

- **公開訓練起點／本人輸入：** 台鐵歷史失物公告；失物類型、可記得的特徵。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_COMMUTE，C06](research/ORDINARY50_COMMUTE.md)。

**狀態：保留候選；公開訓練爲代理目標。** 同樣叫黑色保溫瓶的公告可能很多，普通人先輸入記得的描述，系統一次問一個自己可能回答的問題，最多兩次，再列仍可能的公告。最低成果是減少錯排除的候選，不是替車站證明物主或實現歸還。

- **公開資料／版本／授權／下載**：臺鐵[遺失物資料15856](https://data.gov.tw/dataset/15856)，OGDL-1、不定期；頁面中繼最後更新2025-04-22。[官方 XML](https://ods.railway.gov.tw/tra-ods-web/ods/download/dataResource/fa9bffce59404be797e40a27a524de12)本次HTTP200、8,293,232 bytes，完整在記憶體以UTF-8解析 **23,919筆**；日期實際範圍2002-02-02至2023-07-17。最新頁面更新時間不等於公告包含2025/2026資料。版本是2026-10-03下載到的靜態舊公告快照，非當日全部待領清單。
- **真字段與代理標籤**：`pickupDate, propertyName, propertyAmt, pickupLocation, keepStationTel, keepStationAddr, propertyFeature`。例「遙控器／黑色／車次228／2019-12-30」；保溫瓶826、悠遊卡1,188等，23,918筆特徵非空但不少泛稱。沒有真實失主申報—公告配對。對同一原公告遮住名稱/特徵/地點/時間字段，產生“同記錄”正對與不同公告負對；由已遮住的實際字段計算哪一個可回答問題最減少候選且保留目標，作爲訓練問題優先序的**代理監督**，不是實際歸還標籤。問題訓練僅用名稱、顏色等非個人辨識字段，不抄聯絡電話訓練。
- **已有作品查核**：政大AI中心[2026遺失物智慧尋道](https://iaic.nccu.edu.tw/achievements/68)已有影像/文字比對與主動推播；[拾光 Shiguang 開發者說明](https://apps.apple.com/tw/app/%E6%8B%BE%E5%85%89shiguang/id6809379666)已有AI物品特徵和匹配。世新[2023學生研究清單](https://im.wp.shu.edu.tw/%E5%80%8B%E4%BA%BA_%E6%A6%AE%E8%AD%BD%E7%89%88/)有影像深度學習失物比對原型，公開只見題名。直接「AI找遺失物」因此撤下。[SIGIR2019澄清問題論文](https://arxiv.org/abs/1907.06554)與作者[Qulac倉庫](https://github.com/aliannejadi/qulac)已研究下一問選擇和離線檢索評估；本題不是發明澄清問句。
- **另外測什麼／簡單對照**：使用學習模型預測不同字段問題的辨別效益，而非只作固定查表。對照不提問的語義排序、總先問類別再顏色、當前候選信息增益固定算法，測試兩問預算下目標保留Top5、錯刪真目標、提問次數、回答“不記得”後的候選保留。重點在**泛稱物品與不確定回答**：顏色高頻時是否問地點/日期更好，不能用強制唯一匹配拿高精度。
- **少量自採與完整組切分**：15件自己的日常物品，手機寫描述、允許3組外觀近似物並讓自己回答遺忘情境，約30–40分鐘；5件調流程、10件物品留測。公告按物品原行與重複公告羣、完整日期切分，所有遮罩/改寫同組；2002–2021開發、2022驗證、2023測試先查各年樣本有效量再定，不能把同公告改寫分兩邊。自家以實體物件組隔開。公網Qulac僅作已有方法參照，**沒有用英語外國問答當臺灣訓練數據**。
- **限制與下一步**：舊快照不能承諾現在還在車站，不顯示持有人姓名或私人帳號。代理問題效益可能高估失主的真實記憶；自家模擬不是發生真實遺失/歸還。展示仍有多個近似候選時應保留歧義與官方查詢入口。第一步標10組高頻同名公告與不確定回答，檢查代理標籤是否確實獎勵“少問而不誤刪”。

- **口徑與代理學習目標**：V4.1（2024-06）說明2019-07起改爲**中位數**，不是舊V3的SpaceMeanSpeed平均車速；當前手冊Speed單位句寫成“秒”有明顯文字不一致，第一版以供應的Speed數值定義門檻，不由該句自行轉換單位。事先固定事件定義：有交通量時連續低於60爲擁塞，未來連續3個5分鐘值達到60，稱持續恢復。樣本可標06:55開始、08:00首個恢復窗、08:10確認；模型只能讀預測時刻以前的前綴，學到首個持續恢復窗的剩餘時間或區間內恢復概率。這是**速度事件代理標籤，不是事故清除真時間、本人車速或所有出口全程順暢**。缺檔及跨日未恢復作刪截，不能用插補宣稱已經清空。
- **已有研究／產品／開源／校內範圍**：[2013臺灣國道事故持續時間分類樹](https://doi.org/10.11175/easts.10.1964)已有事故結束時間研究；[2026多擁塞等級持續時間研究](https://www.sciencedirect.com/science/article/pii/S2214367X25002273)已有持續時間模型。交通部[1968 AI預測公告](https://www.motc.gov.tw/ch/app/news_list/view?id=14&module=news&serno=8a8de7d3-22d1-4729-83ba-ac5bdf610a6c)已有旅行時間與選時；[highway_traffic倉庫](https://github.com/ws97109/highway_traffic)已有M05A過去60分鐘預測未來流量/速度、擁塞傳播及出發建議。本次讀公開README，未重跑其聲稱成績。運研所[資料融合梯度提升旅行時間研究](https://www.iot.gov.tw/uploads/asset/data/66fd126e08577718c2cfaec7/透過資料融合以梯度提升決策樹方法預測高速公路旅行時間之研究.pdf)亦爲直接旅行時間比較。課程Notion完整方法仍不可讀，不據此宣稱無同題。
- **另外測試與簡單對照**：本題另測**短暫速度回升後又堵**的錯誤解除，模型學完整事件剩餘時間而不是把未來每個速度獨立預測後只看一窗。對照同星期/時段平均剩餘時間、當前速度斜率外推、簡單速度預測後固定3窗判定，比較15/30/60分鐘Brier分數、時間區間覆蓋、恢復過早誤報、誤報後30分鐘再堵比例。用戶最大可等時間僅作輸出決策條件，不切不同時間窗湊多題。
- **完整時間／路段分組與自採成本**：公開至少按完整日期和完整事件切分，前期訓練、後期驗證、最後連續28天留測；相鄰門架同方向、同一天相連壅塞簇同組，另留整條路線，不能相近5分鐘隨機拆分。一般人填寫入口/出口與10個完整日期的實際“先等/馬上出發”回饋，約15分鐘；有自家紀錄不等於已證明節省時間。
- **最關鍵限制／下一步**：V4.1還說明3日後覆蓋全日修訂：即時10:00代表09:55–10:00，修訂10:00代表10:00–10:05。因此本次歷史樣本是修訂數據，不能當時已經可見的輸入。舊歷史回放只能證明修訂序列上的事件模型；選定後必須另保存至少30日原始即時快照，與最終修訂序列對照，才可說普通人實時等候建議有效。採集的是公開數據非企業資料，不需要個人駕車30天；本輪尚未建立採集器。缺即時覆核時，展示必須標“歷史回放”，不宣稱系統即時成功。

## U37｜台灣旅行照片裡的同名景點，別被分到另一個城市

- **公開訓練起點／本人輸入：** TaiwanVQA自監督/城市；自家旅行照片、已確認地點。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P01](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 一般旅行者提供已有照片及自己確認的旅程日期／城市，整理成「可確認地點、需要核對」兩組，特別處理同名寺廟、相似建築。先限自家 5–10 個確實去過的地方，不猜精確經緯度。
- **模型與真值：** TaiwanVQA 訓練影像同圖增強做自監督視覺起點，已存在的 `location` 只作城市輔助標籤，不能當精確地標標籤。若後續人工挑出答案明確的地標子集可另比較，目前**不預設已經有足量真地標配對**。本人照片的地點 ID 由 GPS／旅行紀錄及人工對照提供；自己同名景點不靠模型自標。公共自監督模型與私人地點配對任務分開。
- **已有作品：** [Google Photos 官方](https://support.google.com/photos/answer/6153599)已用地標及其他照片估缺失位置；地點相簿與旅程線索都不能宣稱新功能。
- **另測的差異：** 固定自己常去的同名／近似景點清單，測「公共模型＋旅程城市」與「再加入每景點少量自家照片」是否減少**整段旅程被錯分到別城**，同時保留新地方不亂認的比例。若僅加 GPS 篩選就足夠，縮成該基準，不能把篩選冒充模型特色。
- **一般輸入／成本與測試：** 已有 30–60 張照片，人工確認地點；校正與測試分開兩次出遊，同一連拍不跨組。以錯城市率、整旅程歸組正確率及核對張數比較，不只單張準確率。臺灣公共照片直接支持在地外觀；公開包含哪些地標及是否足量仍須統計。沒有自己的旅遊照片就不適合。

## U38｜拍家中的物品，找回屬於它的購買或保固文件

- **公開訓練起點／本人輸入：** TaiwanVQA視覺起點；家用品照片、文件配對、外觀變化。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P02](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 本人先將自家 15–30 件物品與本機文件連一次，之後拍物品，找最可能對應的文件；同款兩件無可見差異就追問，不能猜。
- **模型與真值：** TaiwanVQA 日用品圖做同圖增強的自監督視覺預訓練；公共來源沒有家庭保固文件標籤。本人登記的實體 ID／文件 ID 是真值，模型學跨角度實體配對；文件搜尋由已確認實體連結，不拿文件內姓名作辨識捷徑。
- **已有作品：** [Homebox](https://github.com/sysadminsmedia/homebox)已有家用庫存、照片及保固文件管理；[Homebox companion](https://github.com/Duelion/homebox-companion)已有影像辨識與 AI 查詢；[Yo’LLaVA](https://arxiv.org/abs/2406.09400)已做少量照片個人化與難負例。一般影像盤點、個人物品辨識本身不能當差異。
- **另測的差異：** 每物件總額度固定三張，測自己換外殼／移除貼紙後，如何以一張新視角**替換**舊登記照而少錯連到近似物件文件；比較不更新、隨機替換及依易混淆對選替換照片。必須納入 Yo’LLaVA 型少量照片個人化＋難負例基準，不能只和名稱或通用模型比。測更新後新外觀及旧外觀的錯文件率、重登記時間與需追問次數；只把物件識別換個輸出名稱不足以保留。相同外觀無證據時，須接受無法分辨，不能用私人資料增加就保證準確。
- **一般輸入／成本與測試：** 15–30 件已有家用品、每件約三張登記照片及文件；再由可換外殼／貼紙的少數物件收替換登記照，另一天換背景拍保留測試。舊外觀測試不拿登記照當答案，同一原始圖及同一文件截圖不跨組。不需要公司權限。臺灣日用品照片來源可作基底，但家庭實體配對／照片替換策略及效益沒有公共真值；沒有可測的外觀變化就不推薦此題。

## U39｜掃描舊照片有直條紋，依自己的掃描器修復

- **公開訓練起點／本人輸入：** 故宮CC0低解析圖；已有掃描器、白紙、可評參考。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P03](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 有一般掃描器的人，先掃白紙及少量可重掃照片，得到條紋減輕版本與原圖並排；先限固定掃描器的直向條紋，不承諾所有刮傷修復。
- **模型與真值：** 故宮 CC0 小圖提供原圖，自行加入固定欄、寬度、色偏的條紋形成**合成成對標籤**，訓練影像還原模型。合成原圖不代表家庭掃描真值；自己的乾淨重掃與污染掃描才用來驗證，照片細節不得由模型自由生成。
- **已有作品：** [Deep Photo Scan](https://arxiv.org/abs/2102.06120)已研究手機翻拍老照片的真實退化；條紋去除亦已有 [SSCOR](https://pmc.ncbi.nlm.nih.gov/articles/PMC10480181/)等自校正方法。修復舊照與自校正不是首次。
- **另測的差異：** 在同樣訓練圖下，對照「泛用隨機條紋」與「由自家白紙掃描估出的固定感測器條紋」，比較是否減少照片中文字／細線被一起抹掉。以欄位中位數／FFT 修正作基準；量測條紋殘差和乾淨參考區域的細節誤差，不能只看好不好看。
- **一般輸入／成本與測試：** 白紙數次＋約15–20張可重掃老照；**乾淨參考**須來自同原照先前正常掃描，或確認無條紋設備的重掃再對齊，不能把另一個修復模型输出當真值。沒有乾淨參考則先用同照旋轉90度重掃，排除兩張條紋區後只評未污染重疊區域，報對齊限制，不報完整修復準確度。訓練按故宮作品ID切，私人按原始照片及日期切。未取得真條紋及可評參考前只是可測假設；不要求此輪購買或清潔設備。

## U40｜同一個人換了麥克風，錄音紀錄別把他拆成兩個人

- **公開訓練起點／本人輸入：** 台灣TaigiSpeech語者ID；同意的2–4人、兩裝置短句。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P04](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 經同意的 2–4 位家人或固定同事，各錄幾句；整理短段錄音時，將跨手機／耳麥的同一人維持同一代號。先限非重疊短句，不承諾完整會議分離或辨識陌生人姓名。
- **模型與真值：** TaigiSpeech `speaker_id` 支持對比學習，同語者不同句為正例、其他語者為負例；官方 train／val／test 按人分開。私人麥克風／日期／人 ID 由本人登記。不同語言及通道不是原標籤，不能由意圖 ID 推身份。
- **已有作品：** [pyannote.audio](https://github.com/pyannote/pyannote-audio)已有語者特徵、分段及私人微調；[原論文](https://arxiv.org/abs/1911.01255)已做誰在何時說話。普通語者分群或微調不能當差異，也不假稱已可直接使用其有門檻模型。
- **另測的差異：** 私人錄製額度固定，比較只錄一支麥克風與分額度錄兩種裝置，是否較少出現**同一人被拆群／不同人被併群**。報每人所需分鐘、兩類錯誤及新麥克風效益；一味增錄音或換門檻不是答案。
- **一般輸入／成本與測試：** 每人兩裝置、各10–20句，另一天新句獨立測試，按原始句／日期分組。主結果限兩種已校正裝置的後續錄音；如有第三種未見裝置，另報結果，不和已校正裝置混算。公共台語支持語者基底；若私用國語，另比較語言差異，不能承諾完全轉移。原意圖辨識題與本題的跨裝置身份任務不同。

## U41｜手機晃動時，別把抖腿或搭車都算成走路

- **公開訓練起點／本人輸入：** WISDM三軸活動資料；Android感測資料、短段計時。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P05](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 手機確實隨身攜帶，先估**人工計時短段**的走動分鐘，避免搭車震動、坐著抖腿被當走路；完整一天需再收全天真值，短段结果不能直接外推整日可靠度。不是精確步數、健康診斷，也不能從放桌上的手機知道人離席。
- **模型與真值：** WISDM 的人／活動碼及時間戳支持手機加速度分類，再統計走動時長；自己的走路、坐車及抖腿起訖需計時人工標記。公開沒有車輛震動負例時不能宣稱有；私人負例另收。
- **已有作品：** [台灣研究團隊的 HAR 比較](https://www.techscience.com/cmc/v79n3/57123/html)已用 WISDM／UCI-HAR 分類活動；活動辨識及個人手機適應已有大量前作。
- **另測的差異：** 固定相同少量校正時間，對照只錄走路與加入本人通勤／抖腿負例，測**被誤算的走動分鐘**及漏算分鐘，固定真人計時真值，不拿分類準確率等同整日使用效果。
- **台灣可用條件／一般成本：** 海外資料僅限可讀原始三軸加速度／角速度的 Android 手機、同一 Android API／m/s² 與 radians/s、近 20 Hz 時間戳、口袋放置及同樣活動定義；先實核裝置 API 輸出及放置方式，再按人與整次記錄測試，不以單純縮放代替適配。這是物理感測任務的具體相容條件，台灣作者使用 WISDM 不等於台灣現場證據。本人 5–7 天短段計時＋隨身資料，手機不能取得感測器或總是放桌上就撤下。原始 ZIP 完整讀取待補、自家效果未驗證。

## U42｜吉他和弦一次刷下去，找出哪根弦其實沒響

- **公開訓練起點／本人輸入：** GuitarSet弦別校訂標註；已有木吉他、刷奏與逐弦參考。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P06](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 六弦標準調弦木吉他初學者，以手機錄自己刷的六種常練和弦，顯示缺少的弦候選；不要求每次另逐根彈才能開始檢查，聽不清就保留未知。
- **模型與真值：** GuitarSet 六路拾音／弦別音符可構造「移除某路」的**拾音合成缺弦域**訓練配對；JAMS 音符是原作者估計／校訂標註，和弦有譜面與人工確認，缺弦診斷是派生。這不等於真單麥克風少響一弦，六路混音與手機聲學域須分開測，不將刪拾音通道直接套到原麥克風 WAV。應響弦依目標指法，由人確認，原本不應刷的弦不當錯誤；同音高多弦不可只憑音高直接歸弦。合成訓練須同時含刪弦及衰減某路，分開報完全缺音與很弱兩種情境。單麥克風 WAV 已實讀格式，六路與去混音品質尚須補檢查。自己的刻意悶弦刷奏以逐弦確認及錄製表為真值。
- **已有作品：** [TabCNN 原作者](https://github.com/andywiggins/tab-cnn)已做逐弦品位轉寫；[台灣 App Store 的 Guitar Studio](https://apps.apple.com/tw/app/guitar-chords-tuner-songs/id6799145341)已有依次逐弦檢查與悶弦回饋。一般吉他辨音及和弦糾正不能當特色。
- **另測的差異：** 在「一次完整刷奏、某弦很弱但未完全靜音」下，對照通用轉寫與加入本人六根弦短參考，計漏缺弦／誤判缺弦及需要再逐弦檢查幾次。目標是減少重彈成本，而非重新做逐弦調音器。
- **台灣可用條件／成本與測試：** 限 E–A–D–G–B–E／A440 六弦木吉他，台灣實際教學也用此定義，見[海國樂器調弦說明](https://www.haikuo.com.tw/c3cntpage-c3_95659-c3-6593-12432.html)；不得直接外推電吉他／尼龍弦／其他調弦。六和弦各正常／刻意弱弦錄約 30–60 段，另一天新刷法測試；公共按演奏者／原始段分組，同一六路錄音增強不跨組。聲學相容只支持試驗，不能替代手機錄音驗證。

## U43｜鋼琴同一個音連彈幾次，檢查有沒有少算一次

- **公開訓練起點／本人輸入：** MAESTRO音訊/MIDI；已有可輸出MIDI琴、短練習。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P07](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 有可輸出 MIDI 電子琴的人，手機錄短練習，檢查同音連彈的次數與時間；不用每次接線才能看，但校正／評估先同步錄 MIDI。
- **模型與真值：** MAESTRO 音訊＋MIDI 的 note-on 支持起音模型；作品 CSV 的 duration 不是逐音時間，逐音真值須讀 MIDI 事件。私人同步 MIDI 是彈鍵真值，手機時間軸需獨立對齊；音量或尾音不等於新按鍵。
- **已有作品：** [Onsets and Frames](https://magenta.tensorflow.org/onsets-frames)及其[瀏覽器版本](https://magenta.tensorflow.org/oaf-js)已有逐音起音及 MIDI 轉寫；同音起音偵測不是新方法。
- **另測的差異：** 本人電子琴兩種常用音色、不同力度及連彈間隔，固定少量參考額度，比較只用公用模型、單音色校正、多音色校正後的**同音次數錯誤**與提醒延遲。焦點是家中音色切換後，前一次校正是否失效；不將整首轉寫 F1 當練習次數可靠度。
- **台灣可用條件／一般成本：** [台灣 Yamaha Disklavier 說明](https://tw.yamaha.com/zh/products/musical_instruments/pianos/disklavier/index.html)使用相同 MIDI 介面／音符事件；限定相同音符定義和本人可同步輸出 MIDI 的樂器，電子音色與原競賽聲學琴有差異，必須私人獨立驗證。約 10–20 短句、兩音色，另一天新句測試；按作品／原始演奏及日期分組。沒樂器或 MIDI 真值不推薦。非 N41 踏板衰減，也不是承諾聽力／演奏能力評分。

## U44｜舊裝置插孔分不清 Mini-USB 還是 Micro-USB，指出下一張該怎麼拍

- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P08](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 舊相機／GPS 等裝置的插孔看不出是哪種，提示拍正面或側面；最多補一張，辨識已核對的兩種母座形狀。資料是插座，不能拿來宣稱已學會線材公頭。不是電壓、充電速度或資料傳輸能力判斷。
- **模型與真值：** KiCad 真 CAD 類名／幾何，渲染各視角形成**合成形狀與相機姿態標籤**，學辨識及選下一視角。公開沒有真人補拍成功標籤，第二步視角效益須由實體驗證。

- **台灣可用條件／一般成本：** [台灣 Kingconn Mini USB 母座](https://www.kingconn.com.tw/p/usb-mini)明列 Mini-B、5 pin，實用於早期相機／GPS；[Mouser 台灣同型號 47346-0001](https://www.mouser.tw/ProductDetail/Molex/47346-0001?qs=c2CV6XM0DweJBWaSeyWeCw%3D%3D)明列 MICRO USB B RECEPTACLE，與已讀 CAD 同料號及公／母型式。這支持具體物件相容，未證實所有外殼可辨。試點只用已核 Mini-B／Micro-B 母座幾何，裝置外殼遮擋另測；相似口型不能推出訊號能力。本人約 5–10 件舊裝置，分兩天不同光源、背景拍；按實體裝置／型號分組。不要求買零件或拆機。尚未渲染或完成真人補拍。

## U45｜運動途中搬了手機，前後半次動作不要被接成一次

- **公開訓練起點／本人輸入：** MM-Fit CC BY影片；深蹲短片、中途搬鏡頭；完整次數。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PHOTO_AUDIO_HOBBY，P09](research/ORDINARY50_PHOTO_AUDIO_HOBBY.md)。

- **用途／最低成果：** 一般人在家錄自己原本會做的原地深蹲，中途搬手機換角度後，前後兩個半次不被錯接成完整一次。完整週期先定義為站→下降→重新站起，這只是計數定義；不提供姿勢安全或受傷判斷。
- **模型與真值：** 只使用授權明確的 MM-Fit RGB 影片做時間對比自監督，以已知影像視角擾動形成**合成鏡位變更**代理；學鏡位改變與人動作的區別，並用週期序列做計數。它不是實拍搬手機標籤。完整週期／鏡位變更／是否應接續要人工標，原來源未直接提供；不能把未授權 IMU／pose 包當本題訓練資料。選中後先讀／標 20 段公開深蹲片，沒有相符動作就撤下，不偷偷換資料。真搬手機及鏡位前後半次只能由私人連續影片提供真值。
- **已有作品：** MM-Fit 已做運動／休息自動紀錄；[Pūioio](https://arxiv.org/abs/2308.02420)第13頁已用完整週期，第15頁已在姿態無法可信偵測時暫停／回框繼續，因此**停住、半次、出框本身均不能當差異**；[台灣65屆科展「啞鈴幫我數」](https://www.ntsec.edu.tw/science/detail.aspx?a=21&cat=52&sid=22494)已有六軸辨姿勢及次數。
- **另測的差異：** 比較 Pūioio 型完整週期＋失去人像暫停、偵測大幅畫面改變就一律重設，以及可學習鏡位改變與人動作的序列方案；固定私人標註額度，測**人始終可見但鏡頭被搬動**時的跨鏡位誤接前後半次、漏掉真正完整次數及需人工核對秒數。若一律重設已完全解決，這題撤下，不能把簡單規則換介面算特色。沒有動作影像時不補猜次數。
- **台灣可用條件／一般成本：** 海外影像限原地深蹲、相同站→下降→站完整週期標註與 RGB 30fps／可見身體範圍。用上述幾何週期及本人影像核對定義，測搬鏡頭前後真正身體狀態，而不是假設外國人的動作類名一樣就準確；不學國別健身習慣或健康建議。兩天各15–20短片，含未搬鏡／搬鏡但人仍可見／前後半次，依人及整段影片分組。公開影格及派生標籤都尚待補，是資料已可取得、樣本／本地適配仍待驗的條件候選；不能說計次效果已可靠。

## U46｜基礎計算容易忘，下次只複習最需要的三個單元

- **公開訓練起點／本人輸入：** 台灣均一延遲表現代理；3–4週本人基礎計算練習紀錄。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_PERSONAL_REVIEW，L01](research/ORDINARY50_PERSONAL_REVIEW.md)。

- **用途／最低成果：** 願意練基礎計算的一般人，輸入自己的短練習紀錄；當天只排最多三個需要再練的單元，尤其避免提示後答對就被誤判已熟練。不處理公司業務、學生成績或考試保證。
- **公開資料／實讀狀態：** [台灣均一 v9 正式來源](https://www.kaggle.com/datasets/junyiacademy/learning-activity-public-dataset-by-junyi-academy)，2018/08–2019/07、16,217,311 次作答、作者選取 72,630 位學生、CC BY-NC-SA 4.0；選定後遵守署名／非商業／適用衍生資料同授權。下載免登入，3 GB 作答表不整包下載。本輪 [辦公分支來源 D7](research/ORDINARY50_EVERYDAY_OFFICE.md)重讀 ZIP 首段表頭與兩筆，耗時 33／8 秒、提示 0、一次嘗試及真 `is_correct`。內容表的 389,397-byte CSV、標題／ucid／難度／學段／分類證據承接同日 [TW_MORE_PERSONAL](research/TW_MORE_PERSONAL.md)，該檔有「【基礎】和差問題1」；**沒有完整題幹，不承諾自動出題或解題。** 折扣／百分比的內容單元是否足量須選中後再計數。
- **模型與真值：** 用目前以前的 `uuid,ucid,upid,is_correct,used_hint_cnt,total_attempt_cnt,timestamp_TW`，預測之後至少隔一天、同 `ucid`、該人之前從未做過的 `upid`、無提示／第一次嘗試的正確性。`ucid` 僅是練習單元，不能一概叫精確概念；沒出現後續紀錄是缺標籤，不是答錯。這是派生作答表現，不是直接測熟練度。篩無提示會有選擇偏差，要報覆蓋率；當前事件不能偷看未來提示、結果或日期。
- **已有人做什麼：** [CPKT 作者實作](https://github.com/persai-lab/CIKM2023-CPKT)已有個人化、長期學習／遺忘追蹤；[均一時序預測](https://github.com/rizalfanex/junyi-temporal-learning-prediction)已有下一次作答模型；[MC-CPO v2](https://arxiv.org/html/2604.04251v2)已處理答對與熟練不一致及教學策略。這三個來源本輪重新開啟核對。不能用「個人化」「答對不等於學會」作新穎性主張。
- **本題另測什麼：** 在個人很少練習紀錄與每天固定三單元額度下，以**隔日從未做過的新題獨立答對**作為排序目標；對照最近答對率、一般下一題模型及該延遲目標模型。測被排除複習卻在延遲新題失敗的比例、三名額涵蓋失敗單元的數量及機率校準，另分提示後答對／獨立答對。不能從離線順位就宣稱複習改善學習，實際改善另需前後介入或交叉試驗。
- **一般輸入／成本與獨立測試：** 願意練的人，3–4 週約 20–50 次短練習，記單元、題 ID、是否用提示／一次答對及日期；可自行核對合法題目，不強求提供帳號。公共按人切，私人按日期切，重複同題不跨組；後續新題按人、單元及完整學習時間線判定未見。這是試點規模，不是證明學習效益足夠的樣本數。
- **台灣適用及限制：** 公共是台灣學生，不是假稱成人上班族資料；成人基礎計算及現在題庫對應需私人試驗。若使用者不願練，或隔日未見新題標籤不足，此題撤下，不能偷偷改回普通下一題預測。與 EO14「做得完幾題」不同：此題分配複習名額，目標為延遲獨立成功，EO14是耗時。資料欄位實讀、派生標籤尚未全表計數、模型及私人結果未驗證。

依 [選題技能](../.agents/skills/aiot-topic-review/SKILL.md)及[課程要求](COURSE_REQUIREMENTS.md)保留模型、分析及使用情境；不因網頁或老師要求而授權上傳、建立帳號或公開個人紀錄。不是使用者已接受的短名單。

## U49｜講義照片可能漏頁、重拍，先確認哪三對

- **公開訓練起點／本人輸入：** DRCD有序文字塊代理；合法講義照片、原PDF留作真值。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_EXTRA_DESKTOP，ED01](research/ORDINARY50_EXTRA_DESKTOP.md)。

- **用途／輸入／最低成果：** 自己拍的讀書講義照片，頁碼沒有拍到，還可能漏拍或重拍；給本人三次人工確認額度。顯示最值得先看的一對前／後頁，提供「接得上、可能中間有缺頁、像同一頁、不確定」選項。確認後更新已確定的接續與仍有疑問的配對；不把未確認的所有頁硬排成唯一答案，也不填寫缺頁內容。
- **可訓練目標：** D1 人造有序塊先訓練成對接續分類器，分清真相鄰、跳過塊、反序與重複。另在已知原序的擾動集合中模擬人工回答，記錄確認某對後減少多少錯誤接續，作**明示派生的核對效益排序標籤**。可用文字表示、頁尾／頁首接續分數、候選分歧與圖上影響作小排序器特徵。原始塊索引、刪除位置及人造正解只產生標籤，不進模型；不是又訓練生成式助理。
- **資料／適配：** DRCD 繁中 `context`／CC BY-SA 3.0、實讀樣本如 D1；公共代理對應文字接續，**沒有照片缺頁／重頁真標籤，也沒有真實講義頁面版型**。照片先用固定既有文字辨識，另記辨識錯誤；不得將文字塊實驗寫成照片流程成功。自己的完整 PDF 頁序與拍攝頁對應才是本地真值，測試時不提供原 PDF、頁號、檔名序或原 span ID。
- **已有人做什麼：** [Semantic-Guided Reading Order Reconstruction（2026）](https://arxiv.org/html/2607.00596v1)已做單頁及跨多頁的語意閱讀順序，並以產生候選供人確認為用途；不能宣稱它只會單頁或沒有人工核對。[Reading Order Inference（2026）](https://arxiv.org/html/2607.01018v1)已有 causal LM＋BERT NSP 的候選圖、路徑覆蓋與 max-regret 選邊，能優先處理影響大的自動決策；不能把圖或選邊優先順序本身稱新。[FixTools 頁面整理器](https://www.fixtools.io/pdf/reorder-scanned-pdf-pages)已能在縮圖清單手動移頁，不需要重新發明拖曳排序。
- **這題另測／基準：** 上述原論文的明確比較目標是排序錯誤，這卡改測**缺／重頁存在時，有限人工回答實際排除多少錯接，以及剩下多少錯接仍被接受**。不憑「論文沒寫到」宣稱原創。基準包括拍攝順序、全文自動排序後人工看前三對、最低接續信心前三對、圖 max-regret 優先核對、學核對效益的小排序器；每組都使用同文字辨識與同三次回答，不讓模型多讀原 PDF。若 max-regret／最低信心已同樣有效，撤下進一步訓練版本。
- **自家最小驗證：** 5 份本人合法非機密的講義，每份 8–15 頁，共約 40–75 張；保存完整原 PDF，人工確認照片對應原頁。先各留一套完整拍攝，另依記錄漏掉一頁或重拍一頁、遮去頁碼、打散；**這些仍是本地受控缺重頁，不稱自然失誤**。另留一份不刻意干預的實際拍攝，完整／受控／自然三者分報。依整份講義／原 PDF 分組，任何重拍、裁切、OCR 變體及擾動版本均留同組，至少兩份完全新講義只測試。比較 1／3／5 次確認下的錯接排除數、錯接被接受數、缺／重頁漏報、無效核對次數及本人核對秒數；由獨立真值計數，不只報模型信心上升。
- **限制／下一步：** 獨立投影片、練習題每頁內容各自完整，語意未必提供順序；缺第一／末頁更可能沒有兩側線索。可說「無法從內容判定」，不能宣稱知道缺了幾頁。若日常原 PDF 本來就在手邊，先以原檔逐頁匹配，沒有必要用模型猜。第一步拿一份 10 頁真講義測三次核對是否真能省時；若不成立，本題淘汰。

## U50｜影片開頭對得上，後面嘴巴和聲音卻越差越多

- **公開訓練起點／本人輸入：** Blender成片時間變換代理；有原檔的轉檔影片。
- **完整來源、授權、樣本狀態與原卡：** [ORDINARY50_EXTRA_DESKTOP，ED02](research/ORDINARY50_EXTRA_DESKTOP.md)。

- **用途／輸入／最低成果：** 普通人把自己合法保留的影片轉成另一格式，手調一次延遲後，後面仍越來越不對。日常輸入只有成品的聲音與畫面；輸出多個可判定人聲區間的延遲圖、固定偏移／累積偏移／資料不足，及頭尾各一個核對點。只是找問題與預覽，不自動覆寫原檔、改人聲或產生假嘴型。選題測試保留原檔作真值，部署輸入不提供原檔音軌。
- **可訓練目標：** 待觀看核對 D2 的可見說話區間後，保留原音畫配對，在音訊套已知 `t' = a + b*t`：`a` 是位移，`b` 是時間倍率；標籤是相對原片的人造變換參數與每個時點累積偏差。加入純重新編碼、切鏡／局部跳接、畫面沒有說話者等拒絕例；跳接不是線性漂移，不拿單一直線硬解。先以現成音畫表示或同步分數作特徵，訓練小型時序回歸／拒絕分類器，比較直接加權線性擬合；沒有另造一個配音生成器。**原片不被假設為物理上零延遲**，字幕時間也不作同步真值；合成參數是代理真值，實際轉檔偏差由保留原檔的對應畫面／音訊核實。
- **資料／適配：** D2 CC BY 成片、容器真取樣欄位已讀，可下載但未整包取得；人聲／嘴型可用區間仍需觀看標記，不能以 SRT 自動代替。先限定同成片的數位時間變換；本人影片的新語者、語言、壓縮與鏡頭必須獨立測。偏移模型的公開素材先驗沒有證明所有台灣影片有效。
- **已有人做什麼：** [SyncNet 原作／實作](https://github.com/joonson/syncnet_python)已有嘴型與聲音的同步誤差／信心估計，並非只靠音訊波形。[avsyncdoctor](https://github.com/ahmeddoghri/avsyncdoctor)已在單一 MP4 從閃光／拍手等事件估 offset、clock ratio／drift，接 FFmpeg 修正再測量。[Acrovid AV Sync](https://acrovid.com/audio_video_sync_drift_correction.htm)已自動偵測／修正外部音軌漂移；[avsync](https://github.com/Dhi13man/avsync)已有頻譜對齊和 tempo refinement；[WhisperSync](https://github.com/Bormotoon/WhisperSync)更有線性／局部策略與自動建議。它們不能被說成全部只能改固定延遲；[Syncaila 3.x](https://syncaila.com/help)也明列長段漂移與多種修正核對流程。
- **這題另測／基準：** [AV-SyncBench（2026）](https://arxiv.org/html/2607.00726v1)已含位移、局部抖動及速度變化，故不以三分類或合成擾動作原創。其實驗採 3–13 秒影片、速度 0.8–1.25×與原／擾動配對分數；本卡要測的是**只有轉檔成品時，小幅速率失配是否會讓末段殘留偏差，及系統是否把切鏡／配音的局部差誤當可整段修正的漂移**。這是連續偏差估計與錯修風險的本地比較，不僅換較長窗口。基準為只調固定 offset、容器時長／時間戳規則、各可用區間 SyncNet offset 加權直線、帶拒絕判斷的小時序模型；有拍手／閃光錨點的成品另測 avsyncdoctor，不能將它誤列為必須讀原音軌。若原音軌可作日常輸入，另測音訊波形與現成漂移工具；各比較方法取得的 reference 一致。
- **自家最小驗證：** 先觀看標記公開成片中可見說話者的區間，再做人造 offset／小速率變換；同原鏡頭、同音畫內容及所有重新編碼／擾動都留同組，保留整個未用鏡頭評公開測試。本人兩天各 2 支 2–5 分鐘非機密、確實有原檔的影片，保留轉檔工具／設定及原檔與成品對應；第一天可校正，第二天新內容／另一設定只測試。**真轉檔沒有漂移也是有效負例，不強行用故障參數製造成功故事**。公開人造錯誤與真轉檔分報，量首／中／末段偏差誤差、固定／累積錯判、局部不規則卻建議整段修正的比例、拒絕率與人工核對／反覆調整時間；原檔與成品只在建立真值時對齊，不供預測。
- **限制／下一步：** 畫外旁白、配音、嘴型太小或沒有可見發聲動作，內容同步沒有可靠資訊；不估正確配音延遲。原片固有延遲與所施加的 `a` 必須分開，不能把「恢復合成參數」直接當成絕對音畫同步成功；原片本身有局部差異時也不能歸因於轉檔。長段非線性錯位、容器解讀差異與播放器本身延遲也不能簡單當固定倍率；顯示不能判定。若只有 PTS 重置問題，時間戳規則可能直接解決。第一步只核兩支有原檔的真轉檔及公開原片的說話區間；找不到自然案例、直線擬合已夠準、或模型需要原檔才能奏效，就撤下。
