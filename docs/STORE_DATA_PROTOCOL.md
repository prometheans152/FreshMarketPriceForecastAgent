# TW01 同店報價與預測紀錄協議（低負擔採集）

更新日期：2026-10-03。T10 產出。**本文件是資料協議與採集規則，本回合未採集、未輸入、未驗證任何真實店家資料**；範例均為標記 `simulated` 的虛構示範。

對應結構定義：[store_record_schema.json](../configs/store_record_schema.json)（JSON Schema draft-07，含 `store_quote`、`prediction_record`）；匿名模擬範例：[store_record_example.json](../configs/store_record_example.json)。背景見[設計草案](../design.md)第1節、[模型驗證方案](MODEL_VALIDATION_PLAN.md)第4–6節；品項／單位／B容忍度見[專案設定](../configs/project.yaml)。任務關聯：T14（A/B兩路徑）、T16（真同店A/B對照）、T19–T22（推論與紀錄保存）。

## 1. 目的與範圍

本協議定義三件事，供後續採集、儲存與評估共用同一套口徑：

1. **最小記錄欄位**：使用者現場順手記一筆店價需要哪些欄位（`store_quote`）。
2. **預測凍結與到期回填**：每次查詢保存預測當時的A/B輸出，7／14天後回填同店到期實價（`prediction_record`）。
3. **資料界線**：私人資料放哪裡、模擬資料怎麼標記、訓練/校正與獨立測試怎麼切分。

本協議不採集資料、不要求固定頻率；「3品項」「每週記錄」等數字是舉例，不是使用者承諾。

## 2. 最小記錄欄位（`store_quote`）

單筆現場店價觀測。必填7欄、選填3欄，全部可用 schema 驗證：

| 欄位 | 必填 | 規則與理由 |
| --- | --- | --- |
| `store_id` | 是 | 匿名店家代號，如 `store-A`；格式 `^[A-Za-z0-9_-]+$`。**禁止真實店名、地址、電話**；同一實體店對應固定代號。 |
| `crop_id` | 是 | 標準化品項，對應[專案設定](../configs/project.yaml)：`cabbage`（甘藍/平地高麗菜）、`bok_choy`（青江白菜）、`sponge_gourd`（絲瓜）。新品項先以 `x-` 前綴試記（如 `x-napa_cabbage`），正式納入時同步更新 project.yaml 與 schema enum，並記入[決策紀錄](DECISIONS.md)。 |
| `specification` | 選 | 規格／品種／包裝描述（如「平地高麗菜，半顆切面」）。比較、B輸入與到期回填都必須同規格；無法確認時在 `notes` 說明，不當成「完全相同」。 |
| `observed_at` | 是 | 報價日期/時間，RFC3339 含時區（臺灣 `+08:00`）。預測期限永遠從使用者查詢的日曆日起算。 |
| `price` | 是 | 單價，必為正數。**0代表無價**（對應公開資料惯例），不可記為0元。 |
| `unit` | 是 | 可比單位：`NTD_per_taiwan_jin`（元/台斤）、`NTD_per_kg`（元/公斤），依1台斤＝0.6公斤換算（標準檢驗局衡器規範4.8，2026-10-03查核）。`per_piece`／`per_bunch`／`per_bag`（顆/把/袋）**允許記錄但標 non_comparable**：無重量資訊，不可與每斤/每公斤價比較、換算或合併，也不可作為模型輸入或B上週價。 |
| `is_promotion` | 是 | 是否促銷價。促銷價與常態價不可直接當同一行情比較。 |
| `price_source` | 是 | `shelf_tag`（價籤）、`verbal`（口頭）、`receipt`（收據明細）、`paid`（實付）。可信度不同，評估時可分開看。 |
| `notes` | 選 | 品質、來源細節或其他備註（如「每把3條，無重量資訊」）。 |
| `simulated` | 選 | 只能為 `true`，見第7節；真實紀錄省略此欄。 |

收據或價籤照片可選，只存本機忽略目錄，不進入公開報告（見第8節）。

## 3. 使用者負擔原則

- **順手記錄，不新增行程**：只在使用者本來就要買／本來就在看那項菜時記錄。不要求固定每日記錄、不要求整籃清單、不要求預計重量（原菜籃流程已否決，不恢復）。
- **上週價完全選填**：只在使用者記得且有紀錄（收據、價籤照片、先前記錄）時提供；沒有就走A模式，**不用0、不用公開市場均價、不用記憶猜測補**。
- **回填也順手**：7／14天後剛好再到店才記到期價；不專程跑店補價。目標日沒有觀測就依第5節規則記狀態。
- **一筆約30秒**：必填欄位就是店（預填記憶）、品項、價格、單位、促銷勾選、來源，日期時間自動帶入。
- **採集投入統計**：每月彙總各店／品項筆數、預測凍結數、回填率與大約耗時，作為負擔與資料量的誠實證據；不把任何固定頻率寫成使用者承諾或「已足夠可靠」。

## 4. A/B對照與預測凍結（`prediction_record`）

### 4.1 何時凍結、凍結什麼

- **有可比B輸入的查詢：強制同時凍結A與B兩份輸出**（schema 以 if/then 保證：有 `previous_price` 就必須兩種 `mode` 各一筆；無B輸入則不可出現B輸出）。A-only 查詢也建議凍結A輸出，供「所有A案例」報告使用（驗證方案 §6 第7點）。
- 每份凍結輸出含：`mode`（`without_last_week`/`with_last_week`）、`model_version`（A/B可用不同版本；B為規則候選時版本名標 experimental）、`public_data_cutoff`（預測當時實際使用的最新公開資料日）、`horizons`（7與14天的方向與可用價格估計）。
- **凍結後不可事後重算或改寫**；到期後只新增 `maturity` 回填（依T22，不許到期後重算冒充原預測）。

### 4.2 B輸入可比性核對表

引用[專案設定](../configs/project.yaml) `mode_b`：

| 核對項 | 規則 | 不符時 |
| --- | --- | --- |
| 同店 | `store_id` 相同 | B不可比 |
| 同品項 | `crop_id` 相同 | B不可比 |
| 同規格 | `specification` 一致（或皆空且備註一致） | B不可比 |
| 同單位 | 與今天價同單位，且是可比單位 | B不可比 |
| 日期容忍 | `previous_observed_at` 落在 t−9～t−5（7±2天，`previous_week_tolerance_days: 2`）；實際日期與間隔仍完整保留 | `fallback_mode_a_with_warning`：退回A並警示 |
| 換店／換規格／換單位 | `different_store_or_spec_action: reject_b_keep_a` | 僅出A |

被拒的B輸入**仍以 `store_quote` 保存**（那是真實觀測），並在 `prediction_record.b_reject_reason` 記原因；`previous_price` 欄位只在B實際被採用時填寫。

## 5. 到期回填規則（`maturity`）

`t+7` 與 `t+14` 分別回填，狀態獨立：t+7先成熟、t+14後成熟。

- **回填原則**：只能回填**同店、同品項、同規格、同單位**的到期實價，記 `matured_price`（與預測同單位）、`matured_at`、來源與是否促銷。**結賬總額、他店便宜價、公開市場均價不可替代**這個標籤。
- **outcome 狀態**：

| outcome | 意義 | 處理 |
| --- | --- | --- |
| `matured` | 已取得到期實價 | 必填 `matured_price`、`matured_at`（schema 強制）；其他 outcome 不可帶價格（schema 禁止） |
| `out_of_stock` | 到期日店家缺該品項 | 附 `outcome_note` 原因；**不當作漲跌或持平** |
| `spec_changed` | 規格／單位／包裝改變致不可比 | 附原因；不比較 |
| `store_closed` | 到期日店家未營業／停業 | 附原因 |
| `not_yet` | 尚未到期或尚未回填 | 保留待驗證，**不算進任何成績**；最終仍無觀測（未再到店且無憑證）時維持 `not_yet` 並在 `outcome_note` 註明「無觀測」，該配對自評估排除 |

- 促銷狀態與預測時不同（促銷開始／結束）：仍可回填價格，但必須標 `matured_is_promotion` 並在 `outcome_note` 註明；評估時分開報告或依事前凍結規則處理。
- 缺貨、停業一律附原因，不把缺貨解釋成上漲。

## 6. 訓練／校正與未來獨立測試的切分

依[模型驗證方案](MODEL_VALIDATION_PLAN.md) §6，特別是第6點：

1. **私人試點按查詢日期切分**：較早的做訓練／校正，最新的做獨立測試；不按筆隨機打散。
2. **歸組**：同一店家同一天多次輸入、重複收據與近似記錄歸為一組，組不可跨切分邊界。
3. **成熟條件**（§6 第2點同樣適用私人案例）：訓練／校正案例的 `t+14` 實價須在進入下一段前已取得；分界旁未成熟案例整段移除，不是只刪一兩天。
4. **B訓練案例須真有過去記錄**，不由未來價反算；A/B最終 paired 比較用**同一批B可用案例**（隱藏／提供上週價做配對），不因B資料可得性不同偷換比較集。
5. 每筆凍結配對保存 origin 日、h、target 日、公開截止、標籤來源與成熟時間、split 與排除原因；凍結清單附hash，公開與私人清單分開。
6. 開發中可做時間順序滾動驗證調方法；**看過獨立測試後改模型需另找新的獨立測試**，不沿用原結果。

## 7. 模擬資料標記

- 市場模擬（把市場均價當店）、合成店價、UI測試資料：每筆必帶 `simulated: true`，存放於 `outputs/simulated/`（Git忽略），**永遠不得轉為私人真值**。
- 匯入 `private/store_quotes/` 與 `private/predictions/` 的載入器（T19/T22實作）必須拒絕 `simulated: true` 的紀錄；真實紀錄省略該欄位（schema 只允許 `true` 或不出現，`false` 會被拒）。
- 市場模擬的實驗結果只能標「市場均價實驗」，不可寫成同店成果；本協議所有範例檔案均為模擬示範，不是任何真實店家資料。

## 8. 隱私與存放

- 原始私人紀錄只存 `private/store_quotes/`（店價）與 `private/predictions/`（預測凍結，依T20/T22）；兩者已在 [.gitignore](../.gitignore) 的 `/private/` 忽略範圍。
- 收據／價籤照片可選，只存本機忽略目錄，檔名不可含店名；不進入 Git、SERVER或公開交付。
- 公開報告與文件只用**匿名彙總**（如「store-A：甘藍n筆、中位數x元」），不出現店名、地址、個人消費明細或可重識別的購物紀錄。
- 匯出、去識別與刪除流程依T22實作；關閉保存功能仍可正常查詢。

## 9. 自檢紀錄（2026-10-03，TRAIN_LOCAL）

以系統 Python 3.12.10 + jsonschema 4.26.0 驗證（draft-07、開啟 FormatChecker）：

- `Draft7Validator.check_schema` 通過。
- [範例檔](../configs/store_record_example.json) 3筆 `store_quote`、3筆 `prediction_record` 全數驗證通過。
- 20項負向測試均被正確拒絕，包括：價格0／負值、中文真名店號、未知單位、品項錯字、`simulated:false`、缺時區、多餘欄位、B輸入但缺A或B輸出、無B輸入卻有B輸出、`matured` 缺價格、非 `matured` 帶價格、horizon缺14天、格式錯誤日期。
- 注意：本機未安裝 `rfc3339-validator` 時 jsonschema 的 `date-time` format 會靜默通過，因此 schema 另以 `rfc3339_datetime` 的 pattern 強制時區必填，不依賴選配套件。

以上是schema與範例檢查，**不是任何採集、模型或同店驗證的通過證據**。
