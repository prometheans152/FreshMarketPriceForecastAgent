# 研究補充：文獻、領域知識與設計推理

**現場菜價 7／14 天預測與分析代理人**（Fresh Market Price Forecast Agent）

組長：王彥傑｜組員：鄭筑云、許嘉修、游雅婷

本補充承接 [完整 Proposal](PROPOSAL.md) 與 [設計藍圖](../../design.md)：整理文獻摘要的八欄、AI 技術與領域知識、最接近的 Team17、五個核心思維、三個爭論與十個深問題。所有研究比較依實際已讀範圍，不以「摘要未提及」判定某方法不存在。

## 1. Related Work：AI 技術與菜價領域知識

**AI 技術（約半數論述重點）**：價格預測可用時間序列 ARIMA／ETS、神經網路 LSTM、HHT 趨勢分析、樹模型及整合特徵。[R01] 在批發蔬菜價格比較方法；[R03] 探討零售均價的 HHT；[R07] 是氣象與菜價的決策樹探勘；[H17] 使用氣象、批發行情與 LightGBM 做五日預測。[R02] 用包含私有中盤商紀錄的時間序列對照誤差。這些技術可以學習關係，但不能用不同資料、指標直接排名。

**領域知識（約半數論述重點）**：產地與氣候衝擊首先影響供給與批發交易，再經通路反映到零售；[W1] 為颱風後批發價週變動的歷史統計，[R04] 用電子發票估計通路零售價格。[R06] 顯示消費者輸入購買價並比對行情的場景，而 [R05] 官網已提供趨勢預測文案。批發價（常為元／公斤）、公有市場均價（元／台斤）與一間店的標價有不同母體；品質、規格、單位、促銷與缺貨都會造成不可比。價格多數時候持平但少數時段劇變，因此要有明確日曆期限、缺測規則、強基線與真店核對，不能只展示模型輸出的金額。

**研究鏈條**：Existing Research（市場預測／私有資訊增益／消費者比價各有前作）→ Limitations（預測對象與店家現價不同、期限及驗證設定不同）→ Gap（現場店價錨定、選填私人上週價的增益、同店到期配對）→ Our Project（固定 7／14 天公開資料實驗＋A／B 原型與未來實測）。「本次查核範圍內未見組合」只描述文獻範圍，不宣稱全球首創。

### 最接近的 Team17 [H17]：差異要對到研究對象

| 比較 | Team17 | 本案 |
| --- | --- | --- |
| 研究目標 | 市場價格的未來五日預測，採購時機指南 | 使用者今天店價為基準的精確 t+7／t+14 漲平跌 |
| 輸入 | 批發價、交易量、氣象（滯後與季節特徵） | 公開零售均價＋今天店價；上週同店價選填 |
| 方法 | 六品項各訓練 LightGBM | 首版三品項選 RF／HGB；現價錨定 A、實驗性 B |
| 驗證 | 簡報提供 R²／RMSE／MAE（未獨立重現） | 同一封存測試集宏平均 F1、相對變化 MAE 與強基線；真店 A/B 待驗 |
| 主要研究差異 | 市場與氣象訊號預測、選購指南 | 單店錨定的適用性，及私人上週價是否改善同店到期預測 |

**不可跨案排行**：Team17 的 R²／RMSE／MAE（回歸價位）與本案 macro-F1（三類方向）任務、資料、期間不同。Team17 來源是一份 15 頁的歷屆影像 PDF；2026-10-08 的核對實際目視 11／15 頁（頁 1–4、7–12、15），其他頁依同批紀錄輔助；非全文逐頁實讀，也未重跑它的模型。

## 3. Deep Research：Five Core Mindsets

| 思維 | 核心判斷 | 本案採取的設計／驗證 |
| --- | --- | --- |
| M1 Comparability First | 不同店、品質、規格、單位的標價不可直接比較 | B 須同店／同品項／同規格／可換算單位／上週 7±2 天；不可比回 A。0=缺測 |
| M2 Temporal Integrity | 預測時不可能知道未來標籤，發布還有延遲 | 特徵截至 t−1、同日跨市場同區、標籤 t+h+1 成熟清除、精確日曆日 |
| M3 Strong Baselines First | 價格黏著，簡單動量／不變價可能比 ML 更好 | macro-F1 及相對變化 MAE 均與基線同分母對照；負向結果保留 |
| M4 Public vs Private | 公開均價沒有店家識別，不能偽裝上週私價 | 只有真實輸入才算 B；未來要用同店到期價配對裁決 |
| M5 Error ≠ Utility | 分數高不保證購買決策有效，漏報上漲有成本 | 上漲召回單列；不保證省錢，安排用戶及到期效益驗證 |

## 4. Deep Research：Three Controversies

**爭論一：市場均價能否代表店價？** 可用的觀點：市場供需變化有共同訊號（[W1]、[R04]）；反面的觀點：店家地段、促銷與進貨不同，公開資料沒有店 ID（[R02] 的私人紀錄有額外資訊）。本案只用市場相對變化當 A 的參考假設，再以前瞻真店資料驗證；目前無店價準確率。

**爭論二：複雜 ML 一定比簡單基線好嗎？** 非線性模型可擬合交互作用（[R01]、[H17]）；但本案方向 7 天 0.4218 < 動量 0.4226、14 天 0.4169 < 0.4306，點誤差亦輸不變價。此輪判定複雜模型沒有全面勝出，不以跨研究不同指標辯護。

**爭論三：增加氣象或私人欄位必然有效嗎？** 供給、颱風與價格關聯有歷史證據（[W1]、[R07]、[H17]）；新增資料有延遲與雜訊成本，Team17 在實讀範圍未提供氣象消融。本案不宣稱氣象無效，而將 B 私價增益與其他特徵消融列為要做的實驗。

## 5. Ten Deep Questions（含回答與證據）

1. **為什麼用 macro-F1？** 公開標籤持平占多數；全猜持平能有高 accuracy 卻對 up/down 召回為零。macro-F1 平均三類分數。證據：[public_test_results.json](public_test_results.json) 的 per_class、baselines。
2. **為什麼從今天 t 起算？** 使用者比較的是今日標價與固定到期日；若從最新已公布行情日算，發布延遲會偷換承諾的期限。標籤 r_h=m(t+h)/m(t)−1。證據：模型契約及 [design.md](../../design.md)。
3. **「一顆 30 元」和「一公斤 50 元」怎麼辦？** 無重量的顆／把拒絕；50 元／公斤以 ×0.6 換成 30 元／台斤，保持原單位標示。證據：`src/aiot_price/data/schema.py`、`models/store_adapter.py`。
4. **行情落後十天怎麼辦？** 仍回應 t+7／t+14 的日期定義；目前本機路徑有資料老舊警告，並非所有逾期都立即硬拒，無可用特徵則報不足；不可誤稱已完成全面過期硬拒。證據：`src/aiot_price/models/predict.py`。
5. **±5% 調高／調低有何取捨？** 調高使波動事件更少，調低會將小幅雜訊視為事件；此門檻在測試前已固定，敏感度分析尚未做。證據：`src/aiot_price/data/labels.py`、模型 manifest。
6. **為何此版不增加氣象？** 有供給機制的研究動機，但資料時效、可用性與特徵增益仍要同資料消融；先公平對照動量強基線。證據：[H17]、[W1]、封存結果。
7. **上漲召回只有一成有何意義？** 7 天實際 up 158 筆只抓對 16 筆，14 天 268 筆抓對 23 筆；不應當可靠漲價警報，更不能保證省錢。證據：公開 JSON 的 up recall、confusion_matrix。
8. **如何證明 B 真的改善？** 同一批有上週店價的真店案例，事前凍結 A、B 與資料版本，到 t+7／t+14 回填同店同規格實價，配對比較方向與誤差；缺值標「無法核對」。目前未執行。證據：`src/aiot_price/models/store_adapter.py`、[design.md](../../design.md)。
9. **Team17 R²=0.8061 是否比本案 macro-F1=0.4218 強？** 無法直接比：R² 是價位回歸，macro-F1 是類別辨識，資料與期限不同；必須重現同資料同切分才能比較。
10. **為什麼 LLM 不算價格？颱風後如何處理？** LLM 不能保證數值與訓練工件一致，ForecastEngine 才能留下確定的計算來源；沒有即時颱風因果特徵就不能編造理由，必須顯示資料日期、限制，工具失敗不補值。證據：`src/aiot_price/models/predict.py`、MCP 兩工具契約。
