# 新一輪工作題：辦公、行政與商務檔案分支

查核日期：2026-10-03（臺灣時間）。本檔由辦公分支獨立維護，暫用 O01–O09；正式 W 編號由主代理整合。使用者保留的是原 N18，本檔各題均未選定。

**結果：9 個可進一步比較的方向；另列 4 個資料取得不足的備案，不湊入正式數量。** 全部尚未訓練模型、尚未做工作現場驗證。已取得的原始內容只在記憶體中檢查，沒有新增大型資料檔、帳號或外部上傳。少量詞表／官方表單可訓練特定配對模型，但不能冒充有真實工作決策的完整標籤。

## 共通範圍與查重紀錄

- 依工作區 `aiot-topic-review` 格式，先讀 README、PROJECT_CONTEXT、DECISIONS 與原 N01–N50 概覽。避免 N42–N50 的一般文字／語音辨識、地址、姓名題，也避免 N28 選單金額與 N29 時段文字題。
- 本分支查了官方產品、作者原始開源作品、論文／方法原始庫，以及可公開搜尋的課程或學校作品。學校查詢包含 `site.edu.tw 專題 表單 LayoutLM`、`site.edu.tw 1999 專題 分案`、`site.edu.tw 商標 商品 分類 人工智慧`；本輪沒有找到足以取得完整方法的同題課程專題。搜尋回傳政府市政專題研究與公開原始作品；沒有把「未搜到」寫成原創證明。專案原有課程材料仍是評分條件的依據，以下方法是助理研究方案。
- 公共訓練源都是臺灣政府資料或明確以臺灣教育／專業情境編製的 TMMLU+；外國論文與開源程式僅作既有方法比較，不把外國樣本換繁體就當臺灣訓練資料。
- 模型成果均採「輸入 → 預測 → 對照 → 指標」設計；若代理人功能需要補上，可讓代理整理低信心項、呈現原文與請人確認，不能把代理的猜測當標籤。

## O01 採購範疇寫得很短時，找出容易混淆的標的分類

- **工作用途與普通輸入**：採購承辦或供應商輸入一段「要買什麼／要做什麼」，得到 CPC 候選與缺少的辨別資訊，例如裝置購買與維護工程。使用者只需貼 1–3 句原本已寫的需求，無新增感測器。
- **公共訓練資料與臺灣適用性**：[工程會政府採購標的分類](https://data.gov.tw/dataset/6576)，政府資料開放授權第 1 版、每月更新；本次看到詮釋資料更新日 2023-04-11，不能當實際內容版號。[CpcOpenData.xml](https://web.pcc.gov.tw/osm/public/proctrg/download/CpcOpenData.xml) 以一般 HTTP 讀取成功，UTF-8 樣本已讀：262 列，其中 70 列有「我國採購標的舉例」。欄位是標的分類、標的程式碼、中／英文分類名稱、下層 CPC 細項、我國採購標的舉例。臺灣例子是來源欄位，不只是國際 CPC 的繁體翻譯；例子含工程與裝置情境。沒有取得真實標案的適配／得標決策標籤。
- **如何訓練**：以官方例子及分類名稱 → 真實 CPC 碼作文字配對／排序訓練；相鄰類別作難負例。去除品牌、略去材質的版本只作明示的代理增強，不能代表承辦員實際省略方式。只測有足夠例子的類別，完整 262 類不能靠一兩句假裝分類效能已足夠。
- **已有人做什麼**：[Gov Procurement Analytics](https://github.com/akaiHuang/gov-procurement-analytics) 已用臺灣標案、80 多個關鍵字、排除規則做供應商商機篩選與分類檢索。一般標案搜尋、收藏、依關鍵字分組因此淘汰。
- **這題另測什麼**：固定資料量，比較關鍵字／官方名稱近似搜尋、一般分類器，以及加入公司常用簡稱後的排序器。獨立看「裝置／工程／服務」混淆與模型何時應要求補充用途；報 top-3 命中、相鄰類誤判、固定人工退回比例下的錯誤率。差異成立才保留，不以換 UI 當成果。
- **自家資料與切分**：可加 50–100 段已授權、去掉價格與客戶的需求描述，由採購人員確認候選碼；另留至少 50 段測試。依原始需求／採購專案分組，同一詞條所有改寫放同組。公共資料最小成果可做，但自家公司效果需要上述獨立測試。

## O02 營業項目登入：把「製造、銷售、顧問」的描述分清楚

- **工作用途與普通輸入**：行政或商務人員貼一段公司實際活動，協助查出營業項目候選及哪些動詞改變候選；結果由登入人員確認。輸入是已存在的業務說明，額外負擔低。
- **公共訓練資料**：[營業項目代碼表](https://data.gov.tw/dataset/8295)，臺灣經濟部商業發展署，政府資料開放授權第 1 版、不定期更新，本次詮釋資料日 2026-08-12。[商工資料服務規則](https://data.gcis.nat.gov.tw/od/rule) 所列 ODATA 端點 `FCB90AB1-E382-45CE-8D4F-394861851E28` 本次匿名 GET 成功，`$skip=0&$top=1000` 取得 788 列、下一頁為 0。真實欄位 Category、Category_Name、Classes、Classes_Name、Subcategory、Subcategories_Name、Business_Item、Business_Item_Desc、Business_Item_Content、Dgbas。樣本已讀，定義可區別生產活動與顧問活動；是臺灣官方營業項目，不是海外平臺樣本。
- **訓練目標**：程式碼／名稱／定義形成真實正配對，學習階層式排序；相近產業但活動不同者作難負例。官方定義沒有真實客戶說明的多標籤，所以複合業務的真人判斷需另建小型評估，不自行把每段生成描述當正確登入決策。
- **既有做法**：[官方營業項目查詢](https://gcis.nat.gov.tw/cod/html/catelogo_srh.htm) 已能檢索程式碼；[政府資料標準](https://schema.gov.tw/news/content/250) 也已有 BusinessScopeCode。只做公司資料搜尋與分類碼查詢淘汰。
- **獨立差異與指標**：比較完整關鍵字查詢、一般語意排序與少量公司業務說明校正；控制產業名稱不變、只改活動動詞，看模型是否混淆製造／批發／顧問。衡量 top-3 命中、多活動集合 F1、需補問事項命中與退回人工後的錯誤率。
- **自家資料／切分與取得限制**：50–100 段已授權活動說明作校正，另外 50 段獨立測試；同公司、同活動模板及其改寫同組。原始 `code_v8.xlsx` 連結本次回傳 HTML，未當成 Excel 取得。官方檔案另列長期 API 使用的申請程式；此次成功小量讀取不代表後續大量採集已完成或已申請。

## O03 商標商品詞表改版後，辨識「應退回人工」的新名稱

- **工作用途／負擔**：品牌或商品行政人員貼產品用途與品名；輸出官方詞表涵蓋情況、候選組羣與需人工確認處。原本整理商品清單即可使用，不提供核準或侵權預測。
- **臺灣資料與版本**：[TIPO 商品及服務分類](https://www.tipo.gov.tw/tw/trademarks/979.html)，115.07.01（2026-07-01）版本，提供 1–45 類 PDF／ODT。[第 1 類 PDF](https://www.tipo.gov.tw/wSite/public/Attachment/005/f1782806647664.pdf) 9 頁原文已讀，包含組羣 0101、細分 010101 與商品名稱；沒有下載全部 45 類。官方[改版公告](https://www.tipo.gov.tw/tw/trademarks/649.html) 顯示新增／修改／刪除與組羣異動，可建立版本差異。依[官方網站資料開放宣告](https://www.tipo.gov.tw/tw/tipo1/36-17871.html)使用政府資料開放第 1 版並顯名；另標示限制者不納入。
- **可訓練的真標籤**：官方商品名稱 → 官方類／組羣碼；版本中出現／刪除 → 詞表狀態。這不是產品合法登入、能否核準的標籤。用舊版訓練、最新版新增名稱作時間外測試；陌生名稱的真實適用性仍由承辦員標。
- **已有相同功能，直接淘汰一般版本**：[TIPO 2026-08-03 的商品服務名稱自動推薦](https://www.tipo.gov.tw/tw/tipo1/421-90630.html) 已依輸入推薦名稱，分公告、參考與不可名稱，一次可輸入 20 項；只做 AI 名稱推薦是同功能。
- **實質另測**：模型面對改版新增／刪除詞與公司非標準名稱是否過度自信。比較最新版詞表精確／模糊查詢、一般語意分類、增加少量企業術語後的校正模型。測官方名稱涵蓋判定 F1、錯誤高信心比例、固定覆蓋率下候選碼準確率；不可把「已刪除」自動標成商品禁止使用。
- **自家資料與分組**：可用 50–100 個經承辦員確認的商品說明，另留不同產品系列 50 個測試；同詞、舊新改寫與同產品所有規格同組。若只做公共資料，最小成果是版本外詞辨識，不宣稱企業流程效益。

## O04 設備財產登入：省略品名或材質時，找出容易歸錯的程式碼

- **工作用途／普通輸入**：資產管理、工廠行政或採購人員輸入設備品名、材質、用途，得到財產碼候選及需補充欄位。裝置清冊已有這些資訊，無需拍攝；本次成功源是機械及裝置，先限定此範圍。
- **公共資料與實際取得**：[財物標準分類](https://data.gov.tw/dataset/10893)，臺灣主計總處、政府資料開放第 1 版，不定期，詮釋資料 2026-06-18。[機械及裝置 XML](https://ws.dgbas.gov.tw/001/Upload/461/relfile/11525/234457/machineryxmlfile.xml) 本次 HTTP 200 成功且 XML 原文已讀，約 3.49 MB，11,844 列，其中非空財產號碼 11,074 列。欄位類、項、目、節、財產號碼、財產名稱、單位、主要材質、最低使用年限、備註；樣本確認編號／設備名／材質的對應。什項裝置 XML 本次 403，不能宣稱所有辦公裝置資料已取得。
- **真實學習標籤**：名稱＋材質＋備註 → 財產碼。最低使用年限是制度欄位，不能當裝置實際故障壽命。階層標題列與有碼專案分開，不把空白父節點當資產。
- **已有作品**：[承捷資產系統](https://www.chengjie.com.tw/) 已有財產／物品管理、盤點及行政院分類規範支援；一般資產臺帳與盤點介面淘汰。
- **這題另測**：材質或用途資訊能否降低相似品名的錯碼，及公司裝置縮寫校正後是否仍辨識新裝置。基準為品名查詢及無材質的文字模型；實驗固定同裝置、逐欄移除，再增加少量現場別名。報 top-3、同節細項誤判、未知裝置高信心錯位元速率及人工查詢時間。
- **自家資料與切分**：50–100 個去除資產序號／地點的現場名稱與確認碼，獨立測試另 50 件；同裝置族與其所有增強同組。若工作單位主要是純辦公裝置，需先解決什項來源，不能從已讀的工業機械樣本假設涵蓋。

## O05 FAQ 不直接猜答案：多事項來訊找出要查的發布單位

- **工作用途／輸入**：客服或行政視窗收到同時含兩件事的來訊，模型回傳各事項對應的 FAQ 與發布單位候選，方便人工轉接。使用者貼既有文字；少量實際轉接標記纔有額外負擔。
- **臺灣公共源**：[臺北市市政網站整合平臺 FAQ](https://data.taipei/dataset/detail?id=203f1657-bb4a-45a7-b25f-279b63136645)，臺北資訊局、[政府資料開放第 1 版](https://data.taipei/rule)，不定期。[完整 JSON](https://data.taipei/api/frontstage/tpeod/dataset/resource.download?rid=1e344a1f-b926-4f37-8d92-3862156262e9) 檔案標示 2026-04-17，平臺詮釋資料 2026-07-24；本次成功讀取 8,282 列，樣本含標題、內容、發布單位與日期時間。另讀到[最新 50 筆](https://www.gov.taipei/OpenData.aspx?SN=8E47DBEDAB8AE0D9)，不能以 50 筆假裝完整訓練集。
- **學習與標籤限制**：title → FAQ ID／發布單位是真實配對；「發布單位」是發布者，不保證就是所有詢問的責任單位。將兩則原題組合只形成代理多事項資料；真正來訊有無兩事項與最後轉接正確性需真人標記。不得從答案文字生成不存在的工單成敗。
- **已有人做**：[臺北捷運 AI 客服](https://www.gov.taipei/News_Content.aspx?n=F0DDAF49B89E9413&s=07D3B50F1EB3EC98) 已處理 FAQ 與事件通報；一般 FAQ 問答、RAG 回答、檔案上傳聊天淘汰。
- **另測／對照**：單一最佳 FAQ 查詢，對照可拆多事項的排序器與少量視窗術語校正；測事項數辨識、兩項 FAQ 都命中的比例、發布單位集合 F1、低信心退回比例與人工轉接錯誤。不要把發布者正確率直接報成工單分派正確率。
- **自家資料與 split**：可加 100 段去個資的視窗來訊由承辦者標事項與最後單位，再留 50–100 段未見來訊；同原始 FAQ、相似主旨、人工改寫同組，日期晚者獨立測試。沒有私有資料時只完成「多 FAQ 發布單位檢索」研究。

## O06 1999 分案：對長尾單位與不確定案件少做錯誤自動決定

- **工作用途與負擔**：市民服務或工務行政承辦輸入案件原始敘述，分案模型在低信心時退回人員；也可作企業維修工單分類的研究前置，但跨公司適配尚需自家工單。既有敘述即可，不新增錄音。
- **臺灣真實標籤**：[103 年高雄市 1999 派工資料](https://data.gov.tw/dataset/75777)，高雄市政府、政府資料開放第 1 版；歷史內容是 **2014 年**，本次頁面詮釋資料 2025-06-30、不是 2026 案件。[12 月資源](https://openapi.kcg.gov.tw/Api/Service/Get/a9a3a71e-0dd8-453f-b02d-195ef625bb2c) 本次 HTTP 200，JSON 已讀到 **1,000 筆回傳列**，沒有證明是該月完整資料。欄位 BeforeDesc（原敘述）、UnitName（承辦單位）、InformDesc（案件分類）、Cre_Date、FileNo 等，還有 AfterDesc／結案日期；本題只用辦理前可用欄位，遮除姓名、電話及完整地址。平臺另列各月歷史資源，可分月取得，不須依賴即時 API 才能累積標籤。
- **可訓練內容**：BeforeDesc → UnitName／InformDesc 是真實歷史配對；既有路燈故障樣本已讀。AfterDesc、Close_Date、ReplyUnit 等若含處理結果一律排除輸入，避免洩漏。只能宣稱歷史承辦標籤，不能推論現在局處責任或法律權責。
- **相同做法已出現**：[Noob 的高雄 1999 智慧分案原始說明](https://noob.tw/1999-classifier/) 與[原始程式](https://github.com/NoobTW/kcg-1999-classifier) 已用 BeforeDesc／UnitName、斷詞與貝式方法並測後來月份。一般自動分案與簡單換成深度模型淘汰。
- **實質差異**：檢驗長尾單位容易過度自信的問題，固定自動處理覆蓋率，比較貝式、一般分類器與類別校正／拒答模型，另測少量近月資料校正。指標為單位 macro-F1、固定 70%／90% 覆蓋率的錯派率、長尾召回、ECE 信心誤差，不能只報熱門單位準確率。
- **獨立測試與現場成本**：依 FileNo 及重複敘述分組，再按月向後切；完成多月取得與去重才做時間回測。本次沒有現代現場資料。若換企業內部維修，需要另加約 100 件去個資真實工單校正、另 100 件獨立測試，不能把高雄局處碼重新命名就宣稱適配企業。

- **工作用途／普通輸入**：檔案行政人員提供既有掃描表／PDF，檢查欄位值屬於第幾位申請人、哪一項商品及哪張續頁；先從官方格式限定範圍。只做結構與抄錄確認，不做送件核準或自動簽章。
- **臺灣公共資料**：[TIPO 紙本申請書表](https://www.tipo.gov.tw/tw/trademarks/588.html) 有 70 種表單項目。其[其他商標註冊申請書頁](https://www.tipo.gov.tw/tw/trademarks/588-18584.html) 提供空白表、填寫範例、須知與 ODT，頁面更新 2025-10-27；[空白 ODT](https://www.tipo.gov.tw/wSite/public/Attachment/0/f1745911928035.odt) 本次 HTTP 200、26,142 bytes、ZIP 的 content.xml 已讀：144 段落、4 個表格。[填寫範例 PDF](https://www.tipo.gov.tw/wSite/public/Attachment/0/f1745911927935.pdf) 4 頁已讀，表單修訂日 2024-04-15，有可複製的申請人區、代理人區、商品／服務及續頁。來源是臺灣行政格式；範例人物的國籍不影響版面來源，也不能拿範例人名當自家人名訓練集。依[官方開放宣告](https://www.tipo.gov.tw/tw/tipo1/36-17871.html)顯名。
- **訓練與限制**：先從 ODT 表格結構產生欄位框、區塊 ID 及欄位連結的自監督／代理標籤，再用完全虛構填值渲染為模擬檔案；不是已公開的真實填寫掃描集。人工對公開填寫範例確認小型金標。只讀一個 ODT，不宣稱 70 種都已完整取得或有充足各種手寫標籤。
- **既有研究／產品**：[LayoutXLM 原始庫](https://github.com/microsoft/unilm/blob/master/layoutxlm/README.md) 已做多語檔案實體與關係抽取；[臺灣檔案 OCR 廠商的原始說明](https://www.chiga.com.tw/blog/ocr) 已用 LayoutLM 與版面特徵處理表單。單張欄位 OCR 與通用檔案上傳分析淘汰，外國 XFUND 不納入本題臺灣訓練資料。
- **另測／對照**：固定文字辨識器，比較最近距離配欄、通用版面抽取器、加入區塊／續頁關係訓練；同欄位名在多位申請人與重複續頁上是否串錯。測欄位—區塊關係 F1、跨頁錯配率、整表關係全對率，另外報字元辨識錯誤，不能把兩者混為一項。
- **自家資料／切分／負擔**：可用 20–30 份自行填寫的非敏感模擬表、不同掃描裝置作獨立測試；若用真檔案需既有授權並在本機遮除識別資訊。依完整表單、模板及版本切分，模板所有渲染與掃描在同組；模板外測試未透過前不擴大宣稱所有臺灣行政表單。

## O08 修訂條文比對：條號改了、拆成兩段時仍找對新舊對應

- **工作用途／負擔**：規章或檔案管理人員提供兩版檔案，得到新舊段落對應與新增／刪除候選，方便逐條核對變更。使用原本兩份檔案，無新感測器；只比對檔案，不提供法律適用結論。
- **臺灣公共標籤**：[TIPO 歷年商標法規](https://www.tipo.gov.tw/tw/trademarks/578.html)，[2011 年修正條文對照表頁](https://www.tipo.gov.tw/tw/trademarks/578-19211.html) 的 [111 頁 PDF](https://www.tipo.gov.tw/wSite/public/Attachment/005/f1746499244508.pdf) 原文已讀。有修正條文、原條文、說明並列，官方說明含條次移動，可提供真實對應；這是歷史文字，不能當現行規定。[其他修法版本](https://www.tipo.gov.tw/tw/trademarks/572.html) 可作檔案級分組來源。原文依[政府網站開放宣告](https://www.tipo.gov.tw/tw/tipo1/36-17871.html)顯名。此次未把整份 PDF 完成機器表格標註。
- **如何學習**：人員先確認官方表格各列對應、拆／併、無對應，再訓練段落排序／配對模型；官方表格對應是真標籤，段落抽取與「新增／刪除」仍須依列的空白或說明確認，不能把 PDF 行號自然視為正確配對。
- **既有做法**：[Anthropic amendment-history 原始工作流程](https://github.com/anthropics/claude-for-legal/blob/main/commercial-legal/skills/amendment-history/SKILL.md) 已整理修訂歷史、條號及修改內容；一般檔案摘要、兩版 diff、用 LLM 列變更淘汰。此連結是查重來源，沒有將外部 skill 內容當操作授權。
- **實質差異**：在不提供條號、段落拆合與跨頁表格時，模型能否保住語義對應。控制組為條號規則＋文字 diff、通用語意相似；實驗為官方對照配對訓練，再加入自家公司檔案校正。測匹配 F1、拆／併對應召回、錯把新增段落配到舊段落的比例與人工核對時間。
- **自家資料／split**：可加入 30–50 組已授權匿名檔案的人工對照，另留不同檔案 20 組；公開資料也能先做小型成果。整份法規與修訂版本同組；同一法規不同段落不能隨機散到訓練、測試。合約轉用需實測，不因有法規配對就宣稱法律檔案都適用。

## O09 內訓題回答的信心是否可信：選項換順序後仍知道何時退回人工

- **工作用途與普通輸入**：行政或企業訓練人員提供有已確認答案的內訓題，研究助理在可能答錯時是否可靠退回人員。限定公文管理、一般業務／行銷管理，不把測驗分數當實際工作能力；使用者已有題庫時負擔低。
- **公共資料與臺灣證據**：[iKala TMMLU+](https://huggingface.co/datasets/ikala/tmmluplus)／[作者版本與授權說明](https://huggingface.co/datasets/ikala/tmmluplus/blob/main/README.md)，本次 main 為 v1.1、作者列 MIT，資料卡明列主要反映臺灣語言、教育及專業情境，非僅以公司在臺灣判定。包含 official_document_management、business_management、marketing_management 等。公文管理 [validation CSV](https://huggingface.co/datasets/ikala/tmmluplus/resolve/main/data/official_document_management_val.csv) 本次 HTTP 200、**22 題**，欄位 question、A、B、C、D、answer 已讀，問題涉及臺灣公文管理。作者 train 實際指向 dev，不能說成大量訓練資料；全題庫 test 不拿來調參。
- **真正訓練內容**：先固定回答模型，利用已公佈答案比對回答正誤，訓練小型信心校正器或拒答門檻；不假裝 22 題足以微調完整大型模型。不同學科 validation 合併需另下載確認；少量資料可交叉驗證但仍需報告寬的信賴區間。選項重排會同步重對映 answer，所有重排版本同組。
- **已有作品**：[TMMLU+ 原始評測程式](https://github.com/iKala/ievals) 已測多模型選擇題準確率；一般臺灣題庫問答／考試聊天助理淘汰。
- **另測的差異**：同模型、同問題，比較模型自述信心、單引數校正、加入少量內訓域題目後的校正；評估選項順序造成的信心與回答改變，及高信心錯誤能否被擋住。指標 ECE／Brier、固定覆蓋率的錯答率、選項重排一致性，不能只報選擇題準確率。
- **自家資料與 split**：50–100 題已由訓練人員確認的非機密內訓題，可分 50 題校正與另 50 題測試；沒有此資料時只做公開公文與管理題的校正研究。按原始題目／題幹模板分組，公開 test 保留未見；不得把答錯的題先看答案修 prompt 再算獨立測試。
