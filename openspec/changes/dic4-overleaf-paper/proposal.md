# DIC4｜Overleaf 論文草稿與 OpenSpec 工作流程

## Why
教授白板 DIC4 要求 Overleaf 投稿 draft（修改前／後）、Agent 與 Overleaf MCP（LaTeX），以及 OpenSpec 套用於 GitHub 的 goal / design / tasks。現有 FMPA 已有 DIC3 提案和封存公開回測，須避免把學術草稿寫成模型勝出、真店效益已證實或已投稿。

## What Changes
- 新增獨立 `paper/dic4/v1_before`、`v2_after` 的 LaTeX 論文來源與修訂對照。
- 新增 `docs/dic4/GOALS.md`、工作流及驗證紀錄。
- 保留學術文獻來源層級，明確報告相同母體比較與負向結果。
- 產出 Overleaf 匯入 ZIP；有帳號登入後再於雲端建立並編譯。
- 將 Overleaf 與 GitHub 的實際完成狀態和本機草稿狀態分離。

## Capabilities
### New Capabilities
- `dic4-manuscript`：可編譯、可追溯的修改前後論文版本與量化一致性。
- `dic4-workflow`：Overleaf 和 OpenSpec / GitHub 流程的狀態及可驗證證據。

## Scope
僅本次 DIC4 新文件／論文／驗證腳本與交付包。不改模型、資料、既有 DIC3、產品源碼、部署或密鑰；不自稱正式期刊論文。 GitHub 推送與任何第三方憑證整合另按實際授權進行。
